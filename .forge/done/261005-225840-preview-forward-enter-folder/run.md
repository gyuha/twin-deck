# run — 미리보기에서 폴더 위의 →는 폴더 안으로 들어가 첫 항목을 미리본다

워크플로우 없이 직접 TDD로 실행했다. 테스트 6개를 먼저 써서 빨간 상태(전진 검사 3개 실패, 회귀 방지 3개는 이미 통과)를 확인한 뒤 구현했다.

## 슬라이스 결과
- S1 `defaults.ts`에 `core.preview.forward` 추가, `→`를 `core.preview.next`에서 옮김(`↓`는 그대로) — ✅ 계획대로
- S2 스토어 `previewForward()`(폴더면 `navigate` 후 첫 항목 미리보기, 없으면 닫기, 아니면 `previewMove(1)`)와 `actions.ts` 핸들러 — ✅ 계획대로
- S3 `docs/05`에 새 액션 행 추가 — ⚠ `core.preview.next`의 키 설명을 고치려 했으나 docs/05에는 그 행이 원래 없어서 새 행만 더했다

## 계획과 달라진 점
- 테스트를 쓰다 `breadcrumb` 헬퍼가 공용이 아니라 로컬 정의라는 점, `"{ArrowDown}".repeat(0)`이 빈 키 입력으로 오류가 나는 점을 고쳤다(테스트 코드 문제였다).
- 하위 폴더만 든 폴더는 첫 하위 폴더를 미리보기로 이어 가고, 거기서 `→`를 한 번 더 누르면 한 단계 더 들어간다(테스트로 고정).
- 숨김 파일만 든 폴더는 숨김 표시가 꺼져 있으면 "항목 없음"으로 보고 미리보기를 닫는다(현재 목록 기준, 의도한 동작).

## DoD baseline → after
1. `vitest -t "미리보기 폴더 진입"` — 0 tests → 6 passed (구현 전 전진 검사 3개 실패, 회귀 방지 3개는 이미 통과)
2. `tsc` — 통과 → 통과 (회귀 방지)

4. 전체 vitest 639 통과 / 1 실패(`pdf-preview` 기준선) (회귀 방지)

## 남은 불확실성

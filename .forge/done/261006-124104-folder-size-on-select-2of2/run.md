## 계획과 달라진 점
- **기존 테스트 4곳의 기대값을 바꿨다.** 폴더를 선택하면 이제 폴더 용량이 계산돼 합산되는 것이 새 기능의 의도라, 이전 규칙("폴더 용량은 더하지 않는다")을 확인하던 테스트가 깨졌다. 계획의 DoD 4는 "기존 `선택 요약` 테스트가 그대로 통과"라고 적었으나 그럴 수 없었다. 처리: `selection-summary.test.tsx`는 설정에서 옵션을 끄고(파일 규칙은 그대로 시험), `navigation.test.tsx`의 전체 선택 테스트는 개수(`파일: 3/3, 폴더: 2/2`)만 확인하게 했다.
- **경쟁 상태를 하나 찾아 고쳤다.** 계산 중에 선택을 풀었다가 계산이 취소되어 돌아오기 전에 다시 선택하면, 계산 완료 후 다시 계산할 계기가 없어 크기가 영영 안 나왔다. 테스트로 재현(수정 전 실패)한 뒤, 계산이 끝날 때 입력 기록을 비워 다시 세게 고쳤다. 이를 시험하려고 `FakeBackend`에 `dirSizePollMs`를 더했다.
- 목록·선택·옵션이 그대로면 다시 세지 않도록 입력 참조를 비교한다(커서 이동마다 10만 항목을 훑지 않으려는 것).
- 캐시 초기화는 "폴더를 다시 읽을 때 그 폴더의 직계 항목 캐시를 지운다"로 구현했다. 새로 고침·파일 변경 감지·이동이 모두 목록 재읽기를 거치기 때문이다. 이동해서 떠난 폴더의 캐시는 그 폴더에 돌아와 다시 읽을 때까지 메모리에 남는다(작음).
- 옵션을 끄면 계산해 둔 크기를 모두 지운다.

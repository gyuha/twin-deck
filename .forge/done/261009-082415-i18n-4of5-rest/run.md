# 실행 기록 — Rust 문구와 lib 문구를 번역 가능하게 (이슈 #32 4/5)

직접 처리했다.

## 조각별 결과
- S1 남은 TS 문구 이동 — ✅ 3/5에서 이미 끝냈다(lib 5개 파일 포함). 이 작업에서 추가한 것은 없다
- S2 Rust 문구 — ⚠ **계획과 다르게** 구현했다. 계획은 "화면에 보이는 Rust 오류를 오류 종류 코드로 바꾸고 프런트가 번역"이었다. Rust 소스의 한국어 문자열 리터럴이 178개(26개 파일)라 코드화는 Rust 전체를 바꾸는 일이고 ADR 수준 결정이라 범위 밖(비목표: Rust 로직 변경)으로 판단했다. 대신 **영어 대응표 + 소스 검사 테스트** 방식으로 했다.
  - `i18n/rust.ts`: `RUST_MESSAGES`(한국어 템플릿 → 영어, 140여 개), `RUST_INTERNAL`(개발자용 진단·조각 43개), `translateRust`(자리표시자 `{}`·`{이름}`·`{0}` 매칭, 오류 속 오류는 3번까지 반복)
  - 적용 지점: `BackendError` 생성 시(ts-client에 `setBackendErrorTranslator` 훅 추가, store가 `rustText`를 건다), 작업 오류 목록(Dialog·Queue), 설정 경고, 가상 탭 경고, **폴더 미리보기 본문(폴더일 때만)**
  - `i18n-rust-messages.test.ts`: Rust 소스를 읽어 모든 한국어 리터럴이 대응표나 내부 목록에 있는지, 낡은 항목이 없는지, 영어에 한글이 없는지, 자리표시자 개수가 같은지 확인한다. 새 한국어 오류 문구를 Rust에 넣으면 이 테스트가 실패한다.

## 한계(정직하게)
- 이 방식은 한국어 문구를 정규식으로 찾아 바꾸는 우회다. Rust 문구를 고치면 대응표를 같이 고쳐야 하고(테스트가 알려 준다), 사용자 데이터가 섞인 문구는 값 자리만 보존한다. 근본 해결은 오류 코드화이고 별도 작업이다.
- `packages/keybinds`·`packages/actions`가 내는 키 설정 경고 문구(`Keymap.warnings`)와 앱 안내 문구 일부는 아직 한국어다(C3·C4 검사 밖).
- 사용자 파일 내용(텍스트 미리보기)은 번역하지 않는다. 폴더 트리 본문만 바꾼다.

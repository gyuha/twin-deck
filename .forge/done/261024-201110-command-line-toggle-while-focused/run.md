# RUN — 명령어 줄 입력칸에 포커스가 있을 때도 토글 키가 동작한다 (이슈 #119)

작업 규모가 작아(소스 한 줄 + 시험 3개) 계획의 "작은 일은 단일 에이전트로 직접 처리"에 따라 Workflow 없이 이 세션에서 직접 실행했다(fg-loop 구동 중).

## 조각별 결과
- S1 `useKeyboard.ts`가 명령어 줄 입력칸의 이벤트 중 토글 계열(`core.view.command_line`)만 키맵으로 넘기고, 시험 3개(포커스 중 `Ctrl+Shift+K`, `Ctrl+Shift+L`, 입력 보호)를 `run-command.test.tsx`에 추가 — ✅ as planned

## 계획과 실제의 차이
- 시험 이름을 `-t` 필터로 고르는 완료 정의 때문에 이름을 정규식에 안전하게 바꿨다. 처음 이름 `...Ctrl+A...`는 `+`가 정규식 기호라 필터에 안 걸렸다(0개 실행). 이름을 "…(입력 보호)"로 바꾸고 `loop.md`의 C2 필터도 `-t "입력 보호"`로 맞췄다. 확인(C2)은 "시험이 1개 이상 실행되어 통과"여야 한다는 문구 덕에 0개 실행을 통과로 읽지 않았다.
- 별도 계획 변경 없음. 모호한 점 없음.

## DoD baseline → after
- 재현 시험(`-t "입력칸에 포커스가 있어도"`): 수정 전 2개 모두 실패(red) → 수정 후 2개 통과(green). 시험이 repo에 들어오기 전에는 0개 실행(전방 검사, 미충족이 기대 상태).
- 입력 보호 시험(`-t "입력 보호"`): 수정 전 통과 → 수정 후 통과(회귀 보호 검사라 미리 통과하는 것이 기대 상태: 수정 전에는 입력칸이 모든 키를 무시했고, 수정 후에도 토글 키 말고는 무시한다).
- `Ctrl+K`가 꺼진 줄을 켜고 포커스를 주는 기존 시험: 통과 → 통과(회귀 보호).
- 회귀 `bunx vitest run` 전체: 수정 전(직전 main) 194 files 통과 → 수정 후 194 files, 1637 tests 통과, 1 skipped(기존). `bunx tsc --noEmit`: 오류 없음 → 오류 없음.
- 실제 앱(WKWebView)에서는 확인하지 못했다.

## Rulings
- 시험 이름의 정규식 기호 문제로 이름과 C2 필터를 바꿈(계획 문구 수정이 아니라 시험 이름 조정).

# run — 상태 줄에 선택/전체 용량·파일·폴더 수를 표시한다 (Double Commander 방식)

워크플로우 없이 직접 TDD로 실행했다. 테스트(단위 3개 + 화면 5개)와 기존 테스트 기대값 변경을 먼저 하고 빨간 상태를 확인한 뒤 구현했다.

## 슬라이스 결과
- S1 순수 함수 `selectionSummary(entries, selection)`(`lib/selectionSummary.ts`)와 단위 테스트 — ✅ 계획대로
- S2 `StatusBar`가 활성 탭의 항목·선택으로 `선택: 12.3 MB / 45.7 MB, 파일: 2/6, 폴더: 1/2`를 그린다 — ✅ 계획대로. 기존 테스트 3개를 새 형식으로 바꿨다
- S3 `docs/07-ui-spec.md`의 상태 줄 예시와 설명 — ✅ 계획대로

## 계획과 달라진 점
- 바꿔야 할 기존 테스트가 3개가 아니라 4개였다. `virtual-list.test.tsx`가 템플릿 문자열(`선택 ${N}개`)로 옛 문구를 확인하고 있어서 처음 검색에서 놓쳤고, 전체 vitest에서 실패해 발견했다(`파일: N/N, 폴더: 0/0`으로 바꿈).
- 선택 용량이 0이면 `0`(단위 없음)으로 쓴다(`선택: 0 / 3.5 KB`). 계획에 적은 규칙을 그대로 구현했다.
- 용량 표기는 소수점 한 자리를 보장하는 기존 `formatSpace`를 재사용했다(`display.size_format`을 따름). 작은 값은 `11 B`처럼 단위만 붙는다.
- 상태 줄은 `useMemo`로 항목·선택이 바뀔 때만 다시 센다(10만 항목 목록에서도 O(N) 한 번).

## DoD baseline → after
1. `vitest -t "선택 요약"` — 0 tests → 8 passed (구현 전 신규 파일이 로드되지 않아 실패)
2. 기존 `선택 N개` 확인 테스트 — 옛 형식으로 통과 → 새 형식으로 바꾼 뒤 구현 전 실패, 구현 후 통과(4곳: keyboard-scenario 2, navigation 1, virtual-list 1)
3. `tsc` — 통과 → 통과 (회귀 방지)
4. `grep -n "선택: " docs/07-ui-spec.md | grep -c "파일:"` — 0 → 2
5. 전체 vitest 647 통과 / 1 실패(`pdf-preview` 기준선)

## 남은 불확실성
- 실제 앱에서 상태 줄이 길어졌을 때(좁은 창, 알림·경고·토글 버튼과 함께) 줄바꿈이 어떻게 되는지는 확인하지 못했다.
- 폴더 안 용량은 계획대로 더하지 않는다(Double Commander는 폴더를 선택해도 용량에 포함하지 않는 설정이 기본).

# 2026-10-08 — 앱 색을 Warp 테마(apps/desktop/themes)로 바꾸고 기본을 Catppuccin으로 한다

## 계획 대비 실제
- 계획대로 된 것: 생성 스크립트와 생성 파일 2개(S1), 색 계산과 대비 검사(S2), `useTheme` 교체(S3), Rust 이름 검증(S4), 설정 화면·문서(S5). DoD 1~6 모두 충족, vitest 927 → 941, `vite build` 성공.
- 차이:
  - 계획의 "흐린 글자는 글자색을 50%/40% 섞는다"가 고정 비율로는 안 됐다. 16개 테마(밝은 테마 대부분과 solarized-dark)가 대비 3.0 미만이었다. 대비 하한을 정하고 그것을 넘는 가장 큰 비율을 찾는 `dim()`으로 바꿨다. 계획 단계의 측정(50%에서 31개 실패)이 이미 비율 문제를 알려 줬는데도 40%면 되리라 가정했고, 구현해서 돌려 보고서야 알았다.
  - 강조색 위 글자색(`text-white`)을 바꿔야 하는 곳이 계획에 없었다. 흰/검정 자동 선택을 약속해 놓고 컴포넌트 7곳의 `text-white`를 건드린다는 영향 범위를 세지 않았다. 새 토큰 `--color-accent-ink`와 `@theme` 선언이 필요했다.
  - 기존 테스트 한 건(`list-appearance`)이 `not.toContain("text-accent")` 부분 문자열 검사라 새 클래스 `text-accent-ink`에 걸렸다. 의도를 지킨 채 클래스 단위 비교로 고쳤다.
  - 생성 스크립트의 YAML 파서가 `bright`/`normal` 중첩을 잘못 읽었고(normal이 비었다), 정렬을 파일 이름으로 해서 `github-dark-colorblind`가 `github-dark`보다 앞에 왔다(확장자 때문). 둘 다 테스트가 바로 잡았다.
  - 폴더를 `public/`에서 `apps/desktop/themes/`로 옮기는 요청이 계획 중간에 있었고(번들 방지), 옛 `README.md`는 그 전에 이미 없어져 새로 썼다.
  - 처음 요청은 Dracula 기본이었으나 Dracula가 어두운 변형뿐이라 light와 짝이 안 맞아 Catppuccin(Latte/Mocha)으로 바뀌었다.

## 배운 것
- 다음에는 이렇게:
  - 색을 계산해 쓰는 일이면 계획 단계에서 "모든 테마가 대비 기준을 넘는다"를 DoD 숫자로 못 박고, 비율을 고정하지 말고 하한에서 거꾸로 정한다. 이번에는 측정은 했지만 고정 비율을 계획에 적었다.
  - 토큰을 새로 만들거나 이름이 바뀌는 일은 먼저 `grep`으로 그 클래스를 쓰는 곳 전부를 센다(`text-white` 7곳). 흰/검정 같은 "고정 색" 사용처는 두 갈래(강조색 위 글자 vs 고정 배경 위 글자)로 갈릴 수 있으니 한꺼번에 치환하지 않는다.
  - 클래스 이름을 검사하는 테스트는 부분 문자열이 아니라 클래스 단위로 쓴다(`className.split(/\s+/)`). 접두사를 공유하는 새 클래스가 생기면 깨진다.
  - 생성기에는 "최신인가" 테스트와 별개로 값이 올바른지(`normal` ≠ `bright`) 검사하는 테스트를 같이 둔다. 둘이 함께 있어서 파서 버그를 즉시 잡았다.
- 남은 불확실성:
  - 실제 앱에서 색이 보기 좋은지는 모른다(표면 단계의 구분, solarized-light 글자 대비 4.1, 어두운 테마의 선택·호버 구분). jsdom은 CSS를 계산하지 못한다.
  - 설정을 읽기 전 첫 그림의 깜빡임(spaceui dark/light 기본값 → 설정의 테마)이 거슬리는지 모른다.
  - 테마 색이 생성된 TS로 앱에 들어가므로 테마별 라이선스 확인이 릴리스 전에 필요하다.

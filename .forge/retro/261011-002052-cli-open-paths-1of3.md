# 2026-10-11 — td 명령 핵심: 터미널에서 넘긴 폴더를 앱의 왼쪽·오른쪽 패널에 새 탭으로 연다 (이슈 #45, 1/3)

## Plan vs actual
- What went as planned: 인수 해석(`cli.rs`)·단일 인스턴스·시작 인수 상태·ts-client·스토어까지 계획대로. 순수 함수를 TDD로 먼저 고정한 것이 잘 맞았다(10건 red → green).
- Divergences:
  - 터미널에서 떨어져 나올 때 `current_exe()`를 그대로 쓰면 링크 경로(`/opt/homebrew/bin/td`)가 되어 번들 리소스 폴더를 못 찾는다. 실제로 `/tmp/td` 링크로 실행해 보다가 발견했고 `canonicalize`한 경로로 바꿨다.
  - 새 플러그인(`single-instance`)이 `capabilities_cover_plugins` 테스트를 깼다(권한 파일이 없는 플러그인). 예외 목록으로 처리.
  - 단일 인스턴스가 켜지면 격리 HOME으로 띄우는 시험 방법(AGENTS.md)이 사용자의 실행 중인 앱으로 새어 들어간다 → `TWIN_DECK_MULTI=1`로 끌 수 있게 했다.
  - 새 Rust 한국어 문구는 `rust.ts` 대응표에 영어를 넣어야 테스트가 통과한다(처음엔 몰랐다).

## Learnings
- Do differently next time: 자동 시험이 닿지 않는 동작(프로세스 분리, 단일 인스턴스)은 개발 빌드를 격리 환경(`HOME`, `TWIN_DECK_MULTI`)으로 직접 실행해 프로세스 수준에서라도 확인한다. 이번에 링크 경로 문제가 그렇게 드러났다. 새 Rust 문구·새 플러그인을 넣을 때는 `i18n-rust-messages`와 `capabilities_cover_plugins`가 걸린다는 것을 미리 계획의 완료 정의에 적는다.
- 창이 앞으로 오는지·탭이 실제로 보이는지는 jsdom과 프로세스 확인으로는 볼 수 없다. 사람 확인으로 남긴 것을 계획 단계에서 명시했고 그대로 보고했다.

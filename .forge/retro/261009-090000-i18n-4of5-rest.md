# 2026-10-09 — 다국어 지원(이슈 #32) 중 Rust 문구와 lib 문구 (4/5, 5개 작업 일괄 회고)

## Plan vs actual
- 계획대로 된 것: 사전·`t()`·설정 키·액션 제목·메뉴(1/5), store 문구 124개(2/5), 영어 화면 검사와 문서(5/5).
- 어긋난 것: 3/5가 `lib/` 파일까지 넓어져 4/5의 TS 부분이 먼저 끝났다(영어 화면 검사가 열 머리글 "이름·크기"를 잡아서). 4/5의 Rust 문구는 계획의 "오류 종류 코드"가 Rust 26개 파일 변경이라 대응표 방식으로 바꿨다(ADR-0016).

## Learnings
- 다음에는 이렇게:
  - "화면에 한글이 없다" 같은 **탐지 테스트를 먼저** 만들고 그 실패 목록을 일감으로 삼는다. 이번에는 allowlist와 영어 화면 검사가 놓친 파일(`lib/format.ts`)을 알려 주었다.
  - 모듈 수준 상수(설정 항목, 컨텍스트 메뉴, 열 제목)는 번역이 로드 시점에 굳는다. getter(`get label()`)로 그릴 때마다 읽게 한다. 지역 변수 `t`와 겹치면 import를 `tr`로 바꾼다.
  - 훅(`useT`)은 가짜 스토어를 쓰는 단위 테스트에서 터지지 않게 스토어가 없어도 동작시킨다(`windows-paths`, `model-view-limits`가 걸렸다).
  - 한국어 리터럴이 박힌 Rust 문구를 모두 번역하려면 코드화가 정공법이다. 대응표는 임시 우회이므로 Rust 문구를 바꿀 때 `i18n-rust-messages.test.ts`가 알려 준다.
  - 계획의 비목표(Rust 로직 변경)와 충돌하면 조용히 넓히지 말고 run.md에 사유를 적고 ADR로 남긴다.
- (QuickLook #115 회고) jsdom은 WebKit의 srcdoc quirks 모드와 sandbox 리스너 제약을 흉내 내지 못한다. 이런 렌더링 가정은 계획에서 "실제 앱 확인(사람)" 항목으로 못 박는다(ADR-0014에 반영됨). `git mv -k`는 추적되지 않는 백로그 파일을 조용히 건너뛰니 승급 직후 `ls .forge/plan.md`로 확인한다.
- 남은 불확실성: 영어 문구의 자연스러움, 실제 앱(네이티브 메뉴)에서의 영어 표시, 키 설정 경고 문구.

# 2026-10-11 — td 명령 배포: Homebrew Cask, Windows 설치 파일, README (이슈 #45, 3/3)

## Plan vs actual
- What went as planned: Cask `binary` 줄(테스트 5건 먼저), README 쌍·`docs/01`·`05`·`09`.
- Divergences:
  - **Windows 설치 훅 설계를 바꿨다.** NSIS 문자열로 `td.cmd`를 쓰고 PATH를 편집하는 대신 훅이 앱을 `--td-install-cli`/`--td-uninstall-cli`로 한 번 실행한다(앱 안 설치 액션과 같은 `td-cli` 코드, 단위 테스트 2건). 실행해 볼 수 없는 NSIS 코드를 줄이려는 판단이었다.
  - Cask 스크립트의 Ruby 설명 주석에 백틱을 넣었더니 JS 템플릿 문자열이 끊겨 스크립트가 깨졌다(테스트가 즉시 잡음). "binary는 app 줄 바로 다음" 테스트는 사이의 주석 한 줄을 허용하도록 바로잡았다.

## Learnings
- Do differently next time: JS 템플릿 문자열로 다른 언어(Ruby Cask) 텍스트를 만들 때는 주석·본문에 백틱과 `${`를 넣지 않는다. 스크립트가 만드는 파일의 형태를 테스트가 이미 지키고 있어서 이런 실수는 바로 드러난다.
- **확인하지 못한 채 남은 것:** Windows 설치 파일(NSIS)은 `${MAINBINARYNAME}`이 훅 안에서 설치된 exe 이름으로 풀린다는 가정이 맞는지, `ExecWait`가 길게 걸리지 않는지를 첫 Windows 빌드에서 사람이 확인해야 한다. Homebrew의 `binary` 링크는 다음 릴리스를 공개해야 tap에 반영된다.

작은 작업이라 워크플로 없이 메인 세션에서 직접 실행했다.

- S1 패널 쌍 박스(`PaneSplit`)에 `min-w-0` 추가 — ⚠ 계획의 1순위(탭 래퍼 `overflow-hidden`)는 효과가 없어 되돌리고 2순위로 해결
- S2 `pane-split.test.tsx`에 `min-w-0` 회귀 테스트 추가 — ✅ 계획대로(수정 전 실패, 수정 뒤 통과)
- S3 전체 vitest·tsc — ✅ 계획대로

## 계획과 달라진 점
- 원인 추정이 틀렸다. 계획에는 "닫기 버튼 래퍼가 넘침을 잘라 내지 않아서"라고 적었다. 하지만 래퍼에 `overflow-hidden`을 넣어도 넘침은 그대로였다(측정: 격리 인스턴스 캡처). 임시 계측 오버레이로 확인한 결과는 이렇다. 패널 쌍 박스가 1275px로 계산되고(창 1169px), `main`이 `scrollLeft 104`만큼 밀려 있었다. 탭 막대의 최소 너비가 "탭 이름 전체 길이의 합"이 되고, 닫기 버튼을 켜면 탭 여백이 `px-2`에서 `px-6`으로 늘어 그 합이 창 너비를 넘는다(추론). 박스에 `min-w-0`가 없어서 이 최소 너비가 그대로 창 밖으로 밀어낸다. 고친 뒤 박스 1169px, `scrollLeft 0`, 패널 585px씩(측정).
- 그래서 닫기 버튼을 끈 상태도 탭이 많거나 이름이 아주 길면 같은 문제가 났을 것이다(추론, 직접 재현은 안 함). 이번 수정이 그 경우도 막는다.
- 이슈 화면은 왼쪽이 넓어지고 오른쪽이 잘렸는데, 재현에서는 `main`의 가로 스크롤 때문에 양쪽이 잘렸다. 원인은 같다(박스가 창보다 넓음).

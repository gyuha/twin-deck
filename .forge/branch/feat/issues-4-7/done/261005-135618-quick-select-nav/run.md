# run — 빠른 선택 중 ↑↓는 일치한 행 사이를 움직이고, Enter는 그 행을 실행한다

워크플로우 없이 직접 실행했다. 테스트를 먼저 써서 빨간 상태를 확인(4개 중 3개 실패, Esc 회귀 테스트는 이미 통과)한 뒤 구현했다.

## 슬라이스 결과
- S1 `↑`/`↓`가 일치 행 사이를 이동(`quickMove` + `useKeyboard`) — ✅ 계획대로
- S2 `quickAccept`가 빠른 선택을 끝낸 뒤 `open()`으로 커서 행을 연다 — ✅ 계획대로
- S3 `docs/07-ui-spec.md` §4.4에 새 동작 반영 — ⚠ 계획은 `docs/05`였으나 05에는 빠른 선택 accept/cancel 설명이 없어 07 §4.4를 고쳤다

## 계획과 달라진 점
- 기존 테스트 `navigation.test.tsx`의 "Enter는 커서를 둔 채 확정한다"가 이슈가 바꾸려는 옛 동작을 못박고 있어서 새 동작에 맞게 기대값을 바꿨다(Enter가 `docs` 폴더로 들어감). 기대값 약화가 아니라 명세 변경이다.
- 일치 행이 없거나 커서가 일치 행이 아닌 곳에 있어도 `↑`/`↓`는 가장 가까운 일치 행으로 가고, 없으면 움직이지 않는다.

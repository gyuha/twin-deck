## 계획과 달라진 점
- 위치는 `u32`라 음수가 안 된다. 그래서 "제목 줄 64px 남음"을 왼쪽·위는 화면 안(`x,y ≥ 0`), 오른쪽은 `x ≤ 화면 너비 − 64`, 아래는 `y ≤ 화면 높이 − 32`로 구현했다. 창을 왼쪽·위로 반쯤 밀어내는 것은 안 된다.
- 값이 없을 때(`null`)는 CSS 기본 배치를 그대로 두고, 끌기를 시작할 때만 같은 값을 숫자로 계산(`defaultRect`)해 기준으로 쓴다. 따라서 값이 없는 동안은 창 크기가 바뀌면 기본 배치가 따라가고, 값이 생기면 고정된다.
- 움직이지 않고 놓으면(클릭·더블클릭의 앞 클릭) 저장하지 않는다. 처음엔 참조 비교라 0 이동도 저장했는데 테스트로 잡아 값 비교로 고쳤다.
- 테스트에서 reopen을 Space로 했더니 열리지 않았다(`→`로 연다). 테스트 가정 오류였고 제품 동작은 건드리지 않았다.

## 남은 불확실성 / 한계
- 실제 WKWebView에서의 끌기 부드러움, 이미지·PDF·비디오가 창 크기를 따라 바뀌는 모습, 모서리 손잡이가 스크롤바와 겹치는 느낌은 확인하지 못했다 [중간].
- 끌기는 `mousemove`로 구현해, 창 밖으로 나간 포인터는 윈도우 이벤트로만 따라간다. 웹뷰 밖(다른 앱 위)에서 놓으면 `mouseup`을 못 받을 수 있다 [낮음].
- 창 크기를 줄였다가 저장된 값을 다시 키워도 되돌아오지 않는다(열 때 보정한 값이 저장되지는 않지만, 끌면 보정값이 기준이 된다).

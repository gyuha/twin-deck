# ADR-0002. 새 모노레포 + 선별 이식

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락

Spacedrive 소스를 활용하는 방법이 세 가지 있었다. 조사 결과는 다음과 같다.

- `sd-core`의 디렉터리 목록 조회는 DB에 인덱싱된 위치만 읽는다. 복사, 볼륨 관리는 `CoreContext`, `LibraryManager`, `SdPath`에 결합되어 있다.
- 독립적으로 떼어 낼 수 있는 것은 `sd-fs-watcher`, `sd-task-system`, `sd-images`, `sd-ffmpeg`(+`sd-utils`), `file-opening*`와 프론트엔드의 키바인드 레지스트리다.
- Spacedrive에는 듀얼 패널이 없다.
- v2는 alpha다.

## 결정

새 모노레포를 만들고, 독립 모듈만 `crates/vendor/`와 패키지의 `vendor/` 아래로 복사해 온다. 얽힌 부분은 로직만 참고해 twin-deck 타입으로 새로 작성한다. 전략은 복사/포팅/참고로 구분하며 [04](../04-spacedrive-reuse.md)에서 항목별로 정한다.

## 결과

- 장점: 듀얼 패널 중심 설계를 할 수 있고, 불필요한 계층(DB, 동기화, P2P)을 끌고 오지 않으며, alpha의 상류 변동에서 분리된다.
- 단점: 파일 목록, 복사 계획, 볼륨 관리 등 코어 기능을 직접 작성해야 한다. 재사용으로 절약되는 범위가 제한적이다.
- 후속: 이식 절차와 출처 기록 규칙 준수. 상류 변경은 수동 비교.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| A. 전체 fork 후 축소 | 제거해야 할 계층이 크고 DB 의존 코드와 얽혀 있어 제거 작업이 신규 작성보다 클 수 있음. alpha 종속 |
| C. `sd-core` 데몬 사용 | 파일 탐색에도 DB 인덱싱이 필요. alpha에 강하게 종속 |

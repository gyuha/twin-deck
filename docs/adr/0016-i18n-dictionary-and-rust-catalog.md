# ADR-0016. 다국어: 직접 만든 사전과 Rust 문구 대응표

- 상태: Accepted
- 날짜: 2026-10-09

## 맥락

이슈 #32로 앱 화면과 네이티브 메뉴를 한국어·영어로 지원한다(앞으로 언어를 늘릴 수 있어야 한다). 화면 문구 약 800줄이 코드에 한글로 박혀 있었고, Rust(26개 파일, 한국어 리터럴 178개)가 오류·경고를 한국어 문자열로 돌려준다. 기존 테스트 3,200여 줄이 한국어 문구를 그대로 비교한다.

## 결정

- 프런트는 `apps/desktop/src/i18n/`의 **직접 만든 사전**(`ko.ts` 원본, `en.ts`)과 `t(키, 매개변수)`를 쓴다. 영어 사전은 한국어 사전과 키가 같아야 하고(타입과 테스트) 값에 한글이 없다. 언어는 `behavior.language`(`ko` 기본)이며 `locales.ts`와 td-config `ENUMS`에 등록해 늘린다. 한국어 값은 원문 그대로라 기존 테스트가 그대로 통과한다.
- Rust 문구는 오류 코드로 바꾸지 않고, `i18n/rust.ts`의 **한국어→영어 대응표**로 화면에서 바꾼다(`BackendError` 생성, 작업 오류, 설정 경고, 폴더 미리보기 본문). Rust 소스를 읽는 테스트(`i18n-rust-messages.test.ts`)가 모든 한국어 리터럴이 대응표나 내부 목록에 있는지 확인한다.
- 화면 소스에 사전 밖 한글이 남는 것은 `i18n-no-hardcoded.test.ts`(allowlist)가, 영어에서 대표 화면에 한글이 남는 것은 `i18n-english-screens.test.tsx`가 막는다.

## 결과

- 장점: 새 의존성이 없고, 기존 테스트가 한국어 기본으로 그대로 통과하며, 언어 추가는 사전 파일 하나와 등록이다. Rust는 한 줄도 바꾸지 않았다.
- 단점: 대응표는 한국어 문구를 정규식으로 찾아 바꾸는 우회라 Rust 문구를 고치면 표도 같이 고쳐야 하고(테스트가 알려 준다) 모르는 문구는 한국어로 남는다. `packages/keybinds`의 키 설정 경고 문구는 대응표 밖이다. 복수형·언어별 문법은 다루지 않는다.
- 후속 작업: 근본 해결은 Rust 오류의 코드화다. 언어가 늘어 복수형·문법이 필요해지면 i18next 같은 라이브러리로 바꾸되, `t()` 뒤에 숨겨 두었으므로 호출하는 쪽은 바뀌지 않는다.

## 검토한 대안

- i18next 같은 라이브러리: 복수형·보간이 있지만 의존성과 번들이 늘고 언어가 둘뿐인 지금은 과하다.
- Rust 오류를 코드(열거형)로: 가장 바르지만 Rust 26개 파일의 오류 형식을 바꾸는 큰 작업이라 이번 범위에서 뺐다.
- 기본 언어를 OS 언어(system)로: 기존 사용자가 갑자기 영어를 볼 수 있어 한국어 기본으로 했다.

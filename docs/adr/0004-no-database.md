# ADR-0004. DB 없이 라이브 조회

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락

Spacedrive는 SeaORM + SQLite에 위치와 파일을 인덱싱하고, 탐색과 검색이 그 인덱스를 읽는다. 파일 관리자는 임의의 폴더를 즉시 열어야 하고 결과는 파일시스템과 일치해야 한다. Marta의 Look Up은 Spotlight에 위임하며 자체 인덱스를 만들지 않는다.

## 결정

DB를 두지 않는다. 디렉터리는 열 때마다 읽어 스트리밍하고, 이후 변경은 `sd-fs-watcher`의 이벤트로 반영한다. Look Up은 라이브 순회 검색으로 시작하고, macOS에서는 선택적으로 Spotlight를 쓴다. 사용자 상태(탭, 창)는 `state.json`에 저장한다.

## 결과

- 장점: 인덱싱 지연, 동기화 불일치, 마이그레이션이 없다. 이식할 코드가 줄어든다.
- 단점: 반복 검색과 큰 폴더의 전체 크기 계산이 매번 순회 비용을 낸다. 캐시가 필요한지는 M2/M3 실측 후 판단한다.
- 후속: 성능 문제가 확인되면 이 ADR을 대체하는 새 ADR(예: 선택적 검색 캐시)을 쓴다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| SQLite 인덱스 | 신선도 유지와 초기 인덱싱 비용이 파일 관리자 사용 방식과 맞지 않음 |
| 메모리 인덱스(Spacedrive ephemeral) | 코드가 인덱서 상태와 결합. 설계만 참고 |

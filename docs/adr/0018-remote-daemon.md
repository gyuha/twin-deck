# ADR-0018. 원격 접속: 원격 PC의 Twin Deck을 헤드리스 데몬으로 띄우고 `td://별칭/경로`로 라우팅한다

- 상태: Proposed (PoC로 확인 중)
- 날짜: 2026-10-15

## 맥락

이슈 #72는 화면 공유 없이 다른 PC의 파일을 로컬 Twin Deck에서 복사·이동·삭제·이름 변경·압축·해제하고, 문서는 로컬로 빠르게 복사해 보는 사용을 제안했다. [ADR-0003](0003-in-process-ipc.md)은 "원격 접속이 범위 밖"이라는 전제로 데몬을 두지 않았고, [00-overview](../00-overview.md)는 원격 파일시스템을 제외했다. 이 ADR은 그 전제를 바꾸는 방향을 정한다.

Paseo(getpaseo/paseo)는 원격 PC에서 데몬이 WebSocket API를 열고, 데스크톱·모바일 앱이 직접 TCP/Tailscale, SSH 터널, 또는 E2E 암호화 릴레이(tweetnacl: Curve25519 + XSalsa20-Poly1305, QR 페어링)로 붙는다.

## 결정

- **원격 PC에도 Twin Deck을 두고, 같은 실행 파일을 창 없는 데몬 모드로 띄운다.** `Service`는 Tauri에 묶여 있지 않아 창 없이 올릴 수 있다. 새 실행 파일은 만들지 않는다([ADR-0017](0017-td-command-is-the-app-executable.md)과 같은 이유).
- **원격 위치는 경로 문자열 하나로 표현한다: `td://별칭/원격경로`.** 별칭은 사용자 설정의 `[remote.hosts.<별칭>]`(주소, 토큰)이다. 토큰은 경로·탭·이력·상태 파일에 섞이지 않는다. 원격 안의 아카이브 경로(`td://별칭/a.zip!/x`)는 통째로 원격 데몬에 넘겨 원격 `CompositeFs`가 처리한다([ADR-0012](0012-archive-path-notation.md)).
- **실행 위치는 경로로 정한다.** 작업의 모든 경로가 같은 원격이면 그 데몬이 실행하고(바이트가 네트워크를 타지 않게), 로컬↔원격을 넘는 전송만 로컬이 스트리밍한다. `CompositeFs`가 이미 위치 조합별로 복사를 분기하므로 "원격" 위치를 하나 더한다.
- **연결은 직접 WebSocket + 토큰 인증부터 한다.** 데몬(`--serve`)은 기본으로 `127.0.0.1:6868`에만 열고(SSH 터널용, Paseo의 6767과 겹치지 않게), 다른 주소는 `--listen`으로만 열며 경고를 남긴다. 토큰은 `TD_REMOTE_TOKEN`이 없으면 시작할 때 무작위로 만든다. 토큰은 화면(웹뷰)으로 보내는 설정에 넣지 않는다. 암호화는 Tailscale·SSH 같은 네트워크 계층에 맡긴다. 연결 시 프로토콜 버전을 맞춰 보고 다르면 거부한다.

## 결과

- 장점: (원격 작업 위임을 구현하면) 원격 안의 압축·해제·휴지통·복사가 원격에서 그대로 돈다. PoC에서는 원격 안 아카이브 읽기만 원격이 처리한다. SSH 서버가 없는 Windows PC도 붙일 수 있다. UI는 경로 문자열만 다루므로 패널·탭·이력이 크게 바뀌지 않는다.
- 단점: 두 PC의 Twin Deck 버전이 맞아야 한다. 데몬은 실행한 사용자 권한으로 파일시스템 전체를 연다. TLS가 없어 신뢰할 수 없는 네트워크에서 직접 열면 토큰과 내용이 평문으로 지난다. 토큰이 설정 파일에 평문으로 남는다.
- 후속 작업: PoC(목록 + 원격→로컬 복사)로 실현 가능성을 확인한 뒤, 로컬→원격 전송, 원격 작업 위임, 호스트 등록 UI, Paseo식 E2E 릴레이와 QR 페어링을 따로 결정한다. 00-overview의 범위와 ADR-0003에 이 결정을 반영한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| SFTP를 `Vfs`로 구현(원격 설치 없음) | 원격 압축·해제를 하려면 파일을 끌어와야 하고, Windows 원격은 OpenSSH 서버 설정이 필요하다. 이슈가 그리는 "원격 Twin Deck을 로컬에서" 쓰는 경험과 다르다 |
| 패널 단위로 원격 `Backend`를 통째로 연결 | 로컬↔원격 복사에 별도 전송 경로가 필요하고, store가 패널마다 다른 Backend를 써야 한다 |
| 원격을 단순 `Vfs`(목록·읽기·쓰기)로만 다룸 | 원격 안 복사·압축도 바이트가 로컬을 거쳐 가서 데몬을 두는 이점이 사라진다 |
| 처음부터 E2E 릴레이 + QR 페어링 | 릴레이 운영과 직접 만든 암호 프로토콜 검토가 필요하고, 파일 전송 대역폭이 릴레이를 지난다. PoC 다음 단계로 미룬다 |

# ADR-0018. SMB 연결은 OS 마운트로 하고, 자체 원격 파일시스템은 만들지 않는다

- 상태: Accepted
- 날짜: 2026-10-15

## 맥락

이슈 #77은 SMB 서버 연결을 관리하고 그 안에서 복사·이동·삭제를 하게 해 달라고 요청한다. [00-overview](../00-overview.md)는 원격 파일시스템(SFTP, SMB 등)을 범위에서 제외했다. 한편 Finder·탐색기로 마운트한 SMB 공유(`/Volumes/<공유>`, `Z:\`)는 이미 로컬 경로라서 지금도 모든 파일 작업이 된다. `td-vfs`의 NFD 재시도(`retry_nfd`)도 SMB 때문에 들어갔다. 실제로 빠져 있는 것은 저장된 서버에 연결하는 수단뿐이다.

## 결정

- **SMB는 OS에 마운트를 맡긴다.** macOS는 NetFS(`NetFSMountURLSync`)로 `/Volumes` 아래에 마운트하고, Windows는 WNet API(`WNetUseConnectionW`, `CONNECT_REDIRECT`)로 빈 드라이브 문자에 연결한다(`net use`는 비밀번호가 명령줄에 실려서 쓰지 않는다). 마운트한 뒤에는 기존 `LocalFs`, 작업 큐, 파일 감시를 그대로 쓴다. Linux는 지원하지 않는다고 알린다.
- **자체 SMB 클라이언트(`Vfs` 원격 구현체)는 만들지 않는다.**
- 저장된 서버 목록(`name`, `host`, `share`, `user`)은 `config.toml`의 `[[smb.servers]]`에 둔다. 비밀번호는 설정 파일에 넣지 않고 OS 키체인(macOS 키체인, Windows 자격 증명 관리자)에 둔다. 설정 파일은 #71로 내보내기·동기화 대상이 되었다.

## 결과

- 장점: 파일 작업, 큐, 충돌 처리, 감시 코드에 원격 분기가 생기지 않는다. 연결과 인증의 안정성은 OS가 맡는다.
- 단점: OS가 지원하는 방식으로만 연결된다(Linux 미지원). 마운트 상태는 앱 밖에서도 바뀐다(Finder에서 꺼내기 등). Windows 경로는 macOS에서 컴파일로만 확인한다. 비밀번호는 기기마다 따로 저장되므로 새 기기에서는 한 번 다시 입력해야 한다.
- 후속: SFTP/FTP(#76)는 OS 마운트로 해결되지 않는다(macOS FTP 마운트는 읽기 전용이고 SFTP 마운트는 기본 지원이 없다). 그래서 원격 `Vfs`가 필요한지는 그 이슈에서 따로 정한다. 이 ADR이 원격 FS를 범위에 넣은 것은 아니다.

## 검토한 대안

- 자체 SMB 클라이언트를 `Vfs`로 구현: OS 마운트 없이 동작한다. 하지만 `Vfs`는 동기 API라 네트워크 지연·재연결·인증·큐 스트리밍을 새로 다뤄야 하고, 검증된 Rust SMB2/3 크레이트도 드물어서 쓰지 않았다.
- macOS `mount_smbfs`/`osascript mount volume`: 비밀번호가 명령줄에 실리거나(`ps`로 보임) 마운트 지점을 직접 만들어야 해서 NetFS를 택했다.
- `open smb://`로 시스템 인증 창에 맡기기: 앱이 비밀번호를 다루지 않는다는 장점이 있다. 하지만 마운트가 끝나는 시점을 알 수 없고 Windows에는 같은 경로가 없어서 쓰지 않았다.

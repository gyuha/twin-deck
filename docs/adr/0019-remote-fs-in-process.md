# ADR-0019. SFTP·FTP는 앱 안의 원격 클라이언트를 `Vfs`로 감싸 패널에 통합한다

- 상태: Accepted
- 날짜: 2026-10-15

## 맥락

이슈 #76은 SFTP·FTP 서버를 저장해 두고 접속해서 파일을 복사·이동하게 해 달라고 요청한다. [ADR-0018](0018-smb-via-os-mount.md)은 SMB를 OS 마운트로 풀었고, FTP/SFTP는 OS 마운트로 해결되지 않아(macOS FTP 마운트는 읽기 전용, SFTP는 기본 지원 없음) 원격 `Vfs`가 필요한지를 이 이슈에서 정하라고 남겼다.

## 결정

- **앱 안에 원격 클라이언트를 두고 `Vfs`로 감싼다.** 패널이 원격 폴더 안으로 들어가고, 복사·이동·삭제·이름 바꾸기는 기존 `Ops`·작업 큐를 그대로 쓴다. 별도 전송 창(다운로드/업로드만)은 만들지 않는다.
- 새 크레이트 `td-remote`가 프로토콜 중립 블로킹 trait `RemoteSession`을 정의하고 FTP(`suppaftp`)와 SFTP 구현을 둔다. `td-vfs`에는 의존하지 않는다(경로는 서버 쪽 `/` 문자열). 동기 `Vfs`에 맞추려고 API는 블로킹이다.
- FTP는 평문만 지원한다(FTPS 제외). 메타데이터 명령은 재사용하는 제어 연결로(끊기면 한 번 재연결), 전송은 전송마다 새 연결로 한다. 목록은 `MLSD`를 먼저 쓰고 서버가 거부하면 `LIST`(유닉스·DOS 형식)로 읽는다.
- SFTP는 `russh`+`russh-sftp`(비동기)를 크레이트 안 전용 런타임으로 감싸 블로킹 API로 쓴다(호출 스레드가 이미 tokio 런타임이면 새 스레드에서 실행해 중첩 `block_on` 패닉을 피한다). 인증은 SSH 비밀번호만이고, **서버 호스트 키는 확인하지 않고 받아들인다**(known_hosts 같은 영구 신뢰 저장소가 없어 중간자 공격을 막지 못한다 — 후속 과제).
- 오류는 `Auth`·`Unreachable`·`NotFound`·`AlreadyExists`·`Other`로 구분해 UI가 비밀번호를 다시 묻거나 메시지를 고를 수 있게 한다.
- 서버 목록은 `config.toml`, 비밀번호는 OS 키체인에 둔다(ADR-0018과 같다).

## 경로 표기

원격 위치는 `VfsPath`에 문자열로 담는다([ADR-0012](0012-archive-path-notation.md)의 `!/`와 같은 이유: UI가 경로를 문자열로 저장하고 브레드크럼·상위 이동을 문자열 연산으로 한다).

```
sftp://<연결 id>/home/me/a.txt     # SFTP 서버의 파일
ftp://<연결 id>/pub/               # FTP 서버의 폴더
sftp://<연결 id>/                  # 연결의 루트 (경로가 비어도 루트)
```

- 연결 id는 `/`를 담지 않는 문자열이고, 열린 세션을 찾는 열쇠다(`RemoteRegistry`). 서버 항목의 표시 이름과 같을 필요는 없다.
- 분해는 `td_vfs::split_remote`, 조립은 `remote_url`이다. `VfsPath::join`은 Windows에서도 `/`로 잇고, `parent`는 연결 루트에서 `None`을 돌려준다(`sftp:` 같은 조각을 만들지 않는다).
- `td_archive::CompositeFs`가 이 접두를 보고 세션으로 보낸다. 원격 안에서의 이름 바꾸기는 같은 연결일 때만 되고, 다른 곳으로의 이동은 복사 뒤 삭제로 처리한다. 원격과 아카이브 사이 복사는 지원하지 않는다. 원격은 휴지통이 없어 영구 삭제만 되고(`can_trash` false), 심볼릭 링크는 가리키는 대상의 종류와 크기로 보이며 만들거나 읽을 수는 없다.
- 원격 폴더에는 파일 감시가 없다(UI가 다시 읽는다).

## 결과

- 장점: 파일 작업·큐·충돌 처리를 새로 만들지 않는다. 같은 프로세스의 가짜 서버로 소켓 수준 테스트가 된다.
- 단점: 동기 API라 네트워크 지연이 호출 스레드를 막는다. 재연결·타임아웃은 세션 단위의 단순한 처리뿐이다. 평문 FTP는 비밀번호와 내용이 암호화되지 않는다(UI에서 경고한다). 원격은 휴지통이 없어 삭제는 영구 삭제다.

## 검토한 대안

- 별도 전송 창(다운로드/업로드만): `Vfs` 통합이 없어 작지만, 원격 폴더 안의 이동·이름 바꾸기·삭제·미리보기가 안 되고 패널 UX와 달라진다.
- OS 마운트(macFUSE·sshfs 등): 사용자가 따로 설치해야 하고 Windows에서 같은 방식이 없다.
- 외부 `sftp`·`curl` 명령 실행: 비밀번호 전달과 출력 파싱이 불안정하고 설치 여부에 기댄다.

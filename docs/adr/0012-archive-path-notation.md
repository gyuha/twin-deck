# ADR-0012. 아카이브 안 경로 표기: `아카이브!/안/경로`

- 상태: Accepted
- 날짜: 2026-09-30

## 맥락

`Vfs` trait로 아카이브를 폴더처럼 다루려면([ADR-0005](0005-vfs-trait.md)) 아카이브 안의 위치를 UI와 Rust가 같은 문자열로 주고받아야 한다. UI는 경로를 문자열로 저장하고(탭, 이력, 상태 복원), 브레드크럼·상위 이동을 문자열 연산으로 한다. 중첩 아카이브(zip 안의 zip)도 표현해야 한다(ARC-03).

## 결정

바깥 아카이브의 경로 뒤에 `!/`를 붙이고 그 뒤에 아카이브 안 경로를 쓴다. 중첩은 `!/`를 반복한다(Java의 jar URL 관례).

```
/home/me/a.zip!/                      # a.zip의 루트
/home/me/a.zip!/docs/readme.md        # a.zip 안의 파일
/home/me/a.zip!/inner.zip!/x.txt      # a.zip 안의 inner.zip 안의 파일
```

분해 규칙(`td_archive::split_archive_path`):

1. `!/`(또는 문자열 끝의 `!`) 앞부분의 **마지막 경로 요소가 아카이브 확장자**여야 아카이브 경계로 본다(zip, jar, war, aar, apk, nupkg, klib, sublime-package, 설정의 추가 확장자, tar, tar.gz, tgz, tar.bz2).
2. 첫 경계(바깥 아카이브)는 호출자가 **실제로 존재하는 파일인지** 확인해 준다. 이 확인을 통과하지 못하면 다음 `!/`를 후보로 삼고, 끝까지 없으면 일반 로컬 경로다.
3. 안쪽 경계는 확장자만으로 판단하고, 실제로 안에 그 항목이 있는지는 열 때 확인한다.

## 결과

- 장점: 문자열 하나로 모든 위치를 표현한다. 브레드크럼·이력·상태 저장·탭 복원이 그대로 동작한다. 상위 폴더 계산은 "아카이브 루트의 부모 = 그 아카이브가 들어 있는 폴더"라는 규칙 하나만 더하면 된다.
- 제약: 이름이 `.zip!` 처럼 아카이브 확장자 뒤에 `!`가 붙은 **실제 폴더**는 로컬 폴더로 인식된다. 바깥 아카이브가 실제 파일이어야 하기 때문에 `foo.zip!`라는 폴더 안의 경로는 (그 이름의 파일이 없으면) 일반 경로로 남는다. 같은 이름의 파일과 폴더가 모두 있는 경우는 파일(아카이브) 해석이 이긴다.
- 제약: 아카이브 안 항목 이름에 `\`가 든 zip은 그대로 두되 추출할 때는 경로 탈출 검사에서 `\`도 구분자로 본다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| `zip://` 같은 URL 스킴 | 로컬 경로와 다른 문자열 계열이 되어 브레드크럼·상위 이동·복원 코드를 모두 분기해야 한다 |
| 경로를 (아카이브, 안 경로) 구조체로 | UI 상태와 IPC 전체를 구조체로 바꿔야 한다 |
| 널 문자 등 특수 구분자 | 화면에 그대로 보이는 경로(브레드크럼, 오류 메시지)에서 읽을 수 없다 |

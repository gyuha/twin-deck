# 07. UI 명세

## 1. 개요

화면은 위에서 아래로 "탭 줄과 브레드크럼 → 두 개의 파일 목록 → (선택) 터미널 → 상태 표시줄 → Action Bar" 순서다. 키보드만으로 모든 동작이 가능해야 하고, 마우스는 보조 수단이다. 시각 디자인은 이 문서에서 확정하지 않으며(토큰 이름과 값은 M2에서 정한다), 여기서는 구조, 상태, 상호작용 규칙을 정한다.

Marta의 화면을 픽셀 단위로 재현하지 않고, 확인된 기능 구조를 따른다.

## 2. 창 레이아웃

```
┌───────────────────────────────────────────────────────────────┐
│ [탭1][탭2][+]                 │ [탭1][+]                  ⟳ 큐 │  ← 창 우상단에 큐 진행 표시
├───────────────────────────────┼───────────────────────────────┤
│ 브레드크럼: /Users/me/docs    │ 브레드크럼: /Volumes/USB      │
├───────────────────────────────┼───────────────────────────────┤
│ 이름            크기  수정일  │ 이름            크기  수정일  │
│▶report.pdf      1.2MB 어제    │ photo.jpg       340KB 3일 전  │
│ notes.md        4KB   오늘    │ archive.zip     12MB  지난주  │
│ ...                           │ ...                           │
├───────────────────────────────┴───────────────────────────────┤
│ 터미널 (선택, 패널별 pty, 숨겨도 계속 실행)                    │
├───────────────────────────────────────────────────────────────┤
│ 상태 표시줄: 선택: 12.4 MB / 84 MB, 파일: 3/10, 폴더: 1/2      │
├───────────────────────────────────────────────────────────────┤
│ F4 편집 │ F5 복사 │ F6 이동 │ F7 새 폴더 │ F8 휴지통 │ ⇧F8 삭제│  ← Action Bar
└───────────────────────────────────────────────────────────────┘
```

- 좌우 패널은 동일한 크기가 기본이며, 가운데 구분선을 끌어 조절할 수 있다. 창 크기를 바꾸면 비율을 유지한다.
- **활성 패널**은 테두리와 커서 행 색으로 구분한다. `Tab`으로 전환한다.
- Action Bar는 설정으로 끌 수 있다(PANE-07).
- 상태 표시줄은 활성 패널의 선택 요약을 Double Commander처럼 `선택: 선택한 용량 / 전체 용량, 파일: 선택/전체, 폴더: 선택/전체`로 보여 준다. 전체는 지금 목록에 보이는 항목만 센다(숨겨진 파일 제외). 용량은 파일(심볼릭 링크 포함)을 더하고, 폴더는 **선택해서 하위 용량을 계산한 것만** 더한다(폴더 용량 계산 참고). 선택이 없으면 선택 용량은 `0`이다. 크기 표기는 소수점 한 자리이고 `display.size_format`을 따른다.
- **폴더 용량 계산**(`display.folder_size_on_select`, 기본 켜짐): 폴더를 *선택*(`Space`/`Insert`, `Ctrl+A`, 클릭 선택)하면 그 폴더의 하위 총 용량을 백그라운드로 계산해, 크기 칸에 계산 중에는 `…`, 끝나면 크기를 보여 주고 상태 줄의 선택·전체 용량에 더한다. 커서만 올렸을 때는 계산하지 않고, 계산하지 않은 폴더는 크기 칸이 비어 있고 전체에도 더해지지 않는다. 한 번에 한 폴더씩 순서대로 계산하며(숨김 파일 포함, 하드 링크는 한 번만, 심볼릭 링크는 따라가지 않고 다른 볼륨은 넘지 않는다), 선택을 풀거나 폴더를 벗어나면 진행 중·대기 중 계산을 멈춘다. 끝난 크기는 선택을 풀어도 그 폴더 목록을 다시 읽기(새로 고침, 파일 변경 감지, 이동) 전까지 남는다. 압축 파일 안과 가상 탭에서는 계산하지 않는다.
- 상태 표시줄 오른쪽 끝에 `설정`·`단축키` 버튼이 보기 토글(숨김 파일·묶어보기·Drive Bar·Action Bar) 앞에 있다(이슈 #40). `묶어보기`(이슈 #69)는 숨김 파일 바로 오른쪽에 있고 누르면 설정 `behavior.table.group_by_modified`(수정일로 묶어 보기)를 켜고 끈다. 설정 화면의 같은 이름 스위치와 값을 공유하며, 묶기가 적용되지 않는 보기(여러 열 보기·가상 탭)에서도 버튼은 보이고 설정 값을 그대로 보인다. 새 액션·단축키는 없다. 메뉴바가 없는 Windows·Linux의 진입점이고 모든 OS에 보이며, `title`에 현재 키(`Mod+,`, `F1`)가 보인다. macOS 메뉴바에는 같은 항목이 앱 메뉴의 `설정…`과 Help 메뉴의 `단축키 목록`으로 있고 글자 뒤에 현재 키를 괄호로 붙인다(네이티브 accelerator는 쓰지 않는다).
- 터미널은 상태 표시줄 위에 위치하며 높이는 재시작 후 복원된다(TERM-02, PANE-05).
- 큐 진행 표시는 창 오른쪽 위에 있다. 클릭하면 팝업이 열린다(Q-02).

## 3. 탭

- 탭은 각 패널의 상단에 있다. 탭마다 위치, 컬럼, 정렬, 커서, 선택, 이력을 따로 갖는다.
- 탭 제목은 현재 폴더 이름이다. 아카이브 안이면 아카이브 이름을 앞에 붙이고, 가상 탭이면 종류(예: "Disk Usage")를 표시한다.
- Recent Locations는 두 패널이 함께 쓰고(탭·패널과 무관) 창을 닫아도 `state.json`에 남는다. 개수는 `behavior.layout.recent_limit`(기본 20)로 정한다(NAV-09).
- 탭을 끌어 같은 패널의 탭 줄 안에서 순서를 바꾸고, **반대쪽 패널의 탭 줄 위에 놓으면 보낸다(패널 간 탭 이동·복사, 이슈 #24)**. 원래 패널에 탭이 둘 이상이면 이동하고(정렬·보기·방문 기록·커서·선택을 그대로 가져간다), 하나뿐이면 복사한다(원래 패널은 그대로 두고 같은 경로의 새 탭을 만든다 — 패널이 탭 0개가 되지 않게). 놓은 자리는 탭 줄에서 가장 가까운 탭의 앞/뒤이고, 보낸 탭이 그 패널의 활성 탭, 그 패널이 활성 패널이 된다. 끄는 동안 놓일 탭 줄이 표시되고 Esc로 취소한다. 검색 결과 같은 가상 탭은 패널 간에 보내지 않는다. **터미널 탭 이동(이슈 #96)**: 터미널 탭은 예외라 반대쪽 탭 줄에 놓으면 보낸다. 복사하지 않고 늘 이동하며(pty 세션이 하나뿐) 같은 탭 id·세션 번호로 대상 자리에 들어가고 세션은 닫지 않는다. 터미널이 그 패널의 마지막 탭이면 원래 패널에는 그 터미널이 시작한 폴더(원격이면 그 원격 폴더)를 보는 파일 탭을 채운다(터미널 탭을 닫을 때와 같다). 터미널 화면(xterm 엔진)과 pty 출력 구독은 패널의 뷰가 아니라 세션이 들고 있어서(`lib/terminalSessions.ts`) 새 패널의 뷰가 같은 화면을 이어 받고, 옮기는 사이에 온 출력도 놓치지 않으며 어느 뷰에도 붙어 있지 않게 되면(탭을 닫거나 셸이 끝남) 다음 틱에 엔진을 해제한다. 파일 목록 위에 놓거나 키보드 단축키로 보내는 것은 지원하지 않는다.
- 설정 `behavior.layout.tab_close_button`(기본 꺼짐, 이슈 #36)을 켜면 모든 탭의 좌우 패딩이 같게 넓어지고(✕ 자리, 호버로 글자가 움직이지 않는다), **마우스를 올린 탭의 오른쪽에 ✕ 버튼**이 보인다. 누르면 그 탭이 닫히며 가운데 클릭과 같이 활성 패널은 바뀌지 않고 끌기도 시작하지 않는다. 패널에 탭이 하나뿐이면 ✕를 숨긴다(마지막 탭은 닫을 수 없다). 꺼져 있으면 탭 모양과 동작은 그대로다.
- 설정 `behavior.layout.tab_position`(`"top"` 기본 | `"bottom"`, 이슈 #67)을 `"bottom"`으로 하면 각 패널의 탭 막대가 그 패널의 파일 목록 아래(패널 하단)에 놓인다. 패널이 둘이라 탭 막대도 패널마다 하나이고 두 패널 모두 따른다. 하단일 때 막대의 경계선은 위쪽에, 활성 탭 강조선은 탭 위쪽에 있다(`underline`·`segments` 두 스타일 모두). 탭 끌기·닫기·키 조작은 위치와 무관하게 같다. 탭 막대를 감추거나 왼쪽·오른쪽에 두는 옵션은 없다
- **연결 아이콘(이슈 #93)**: SMB(`[[smb.servers]]`)·원격(`[[remote.servers]]`) 항목의 `icon`(이모지 1개, 비면 없음)을 연결 메뉴의 항목 이름, 마운트된 SMB 공유의 드라이브 바 볼륨 버튼, 경로 표시줄의 연결 루트 조각(원격은 `sftp://<id>/`, SMB는 마운트 폴더), 그 연결 안에 있는 탭의 이름 앞에 붙인다. 터미널 탭은 시작한 위치(원격 셸이면 그 연결)의 아이콘을 쓴다. 설정의 서버 편집 창에서 넣는다: 아이콘 칸을 누르면(클릭·포커스) 칸 근처에 이모지 선택 팝업이 뜬다. 팝업은 `body`로 포털해 `position: fixed`로 그리므로 편집 창의 크기·스크롤을 바꾸지 않는다(칸 아래에 자리가 모자라면 위로 올려 그린다). 선택기는 `frimousse`이고 전체 이모지를 분류별로 보여 주며 검색 칸(UI 언어 ko·en)이 있다. 이모지 데이터는 앱에 들어 있어(`apps/desktop/public/emojibase/`, `emojibase-data` 16.0.3의 `ko`·`en`, 약 1.5MB) 인터넷 요청 없이 오프라인에서도 된다. 이모지를 누르면 아이콘이 바뀌며 팝업이 닫히고 포커스가 칸으로 돌아온다(**지우기**로 비운다, `Esc`는 팝업만 닫고 바깥을 누르면 닫힌다). 포커스는 팝업이 열려 있어도 칸에 남아서 OS 이모지 선택기 등으로 칸에 직접 입력할 수도 있고, 입력하면 마지막 한 글자만 남는다. SMB 탭은 저장된 항목이 지금 마운트된 위치(`smb_mounts`, 앱 밖에서 마운트한 것 포함)로 알아보며 볼륨 목록을 다시 읽을 때(시작·창 포커스·연결 후) 함께 갱신한다.
- **특수 탭 색(이슈 #92)**: 터미널·SMB·SFTP·FTP·Twin Deck Remote 탭을 종류별 색으로 칠한다(원격 서버에서 연 터미널은 터미널로 본다. 검색 결과 같은 다른 가상 탭은 일반 탭). 설정 `behavior.layout.tab_color_terminal`/`_smb`/`_remote`/`_twindeck`(`"auto"` 기본 | `"off"` | `"#rrggbb"`). `segments`는 활성 여부와 관계없이 탭 배경을 그 색으로 칠하고 활성 탭은 굵은 글씨와 목록 쪽 안쪽 선(글자색)으로 구분한다. `underline`은 이름 앞에 색 점을 붙이고 활성 탭의 밑줄을 그 색으로 칠한다. 자동 색은 OKLCH에서 테마 강조색의 hue를 종류마다 45°·135°·225°·315° 돌리고, 배경 색은 글자와 대비 4.5 이상·앱 배경과 ΔE 0.06 이상(채울 수 없는 테마는 대비를 지키는 것 중 배경과 가장 먼 것), 밑줄·점 색은 앱 배경과 대비 3 이상이 되는 밝기를 고른다. 직접 지정한 색은 그대로 쓰고 글자만 대비 4.5 이상인 색(앱 글자색 또는 흰색·검정)으로 고른다. 색맹 시뮬레이션은 하지 않는다.
- 탭을 **마우스 가운데 버튼**으로 클릭하면 그 탭이 닫힌다(활성 탭이 아니어도, 어느 패널의 탭이든 — 이슈 #27). 활성 탭을 닫으면 이웃 탭이 활성이 되고 다른 탭을 닫으면 활성 탭은 그대로다. 닫는 시점은 버튼을 뗄 때이고(`auxclick`) 가운데 버튼은 탭 끌기를 시작하지 않는다. 검색 결과 같은 가상 탭을 닫으면 진행 중인 작업을 멈춘다.
- Disk Usage treemap 보기의 키(이슈 #29): `←` `→` `↑` `↓`는 화면에서 그 방향으로 인접한 타일로 선택을 옮기고(그 방향에 타일이 없으면 그대로), `Enter`·타일 클릭은 반대쪽 패널에 선택한 폴더를 연다. `Shift+→`·`Mod+Enter`·더블클릭은 선택한 폴더로 내려가 다시 그리고(파일 타일의 `Shift+→`는 미리보기), `Backspace`는 한 단계 위로 올라간다. 목록 보기의 키는 그대로다.
- Disk Usage 탭(목록·treemap 어느 보기든)에서 수식키 없는 `q`를 누르면 그 탭에서 나간다(이슈 #26): 탭을 닫고(진행 중인 스캔은 취소) 이웃 탭으로 돌아가며, 그 패널의 유일한 탭이면 기준 폴더의 일반 탭으로 바뀐다. Quick Select가 진행 중일 때의 `q`는 검색어이고, 한글 입력기에서도 물리 키로 판정한다. 그 대신 Disk Usage 탭에서는 `q`로 시작하는 이름을 Quick Select로 찾을 수 없다.
- 마지막 탭은 닫을 수 없다(닫기 액션은 홈 폴더로 이동). 이는 twin-deck의 결정이며 Marta 동작은 확인하지 못했다 `[알 수 없음]`.

## 4. 파일 목록

### 4.1 목록 보기

목록은 항상 이름과 설정된 컬럼을 가진 행 목록(Table)이다. 한때 있던 열 1~3개 보기(`Alt`와 `Mod`를 누른 채 숫자 0~3)는 열 보기에서 `→` 미리보기를 쓸 수 없는 문제로 없앴다(이슈 #74). 예전 상태 파일에 저장된 다열 보기는 무시하고 표로 연다. Spacedrive의 Grid/Media/Size 뷰는 Marta에 없는 모드이므로 범위 밖이다.

### 4.2 컬럼

컬럼 명세는 `[<|>]이름[:너비]` ([06](06-config-plugins.md#42-컬럼)). 기본 컬럼은 이름, 크기, 수정일이다. 헤더 클릭으로 정렬을 바꿀 수 있고, `core.view.order` 액션으로도 바꾼다. 폴더(폴더를 가리키는 심볼릭 링크 포함)는 어떤 정렬 기준에서도 파일보다 위에 두고, 폴더 묶음 안에서는 선택한 기준으로 정렬한다(이슈 #47). 파일을 가리키거나 끊어진 링크는 파일 쪽에 남는다. 심볼릭 링크는 이름 앞 아이콘 오른쪽 아래에 작은 `↗` 표시가 붙고, 폴더를 가리키는 링크는 폴더 아이콘에 그 표시가 붙는다(파일·끊어진 링크는 파일 아이콘에 표시). 컬럼 너비는 헤더 경계를 끌어 조절한다(이슈 #48). 이름을 뺀 각 컬럼 헤더의 왼쪽 경계가 손잡이이고, 끄는 동안 헤더와 모든 행이 같이 바뀌며(최소 40px, 최대 600px), 마우스를 놓을 때 설정 파일의 `view.table.columns`에 그 컬럼의 `:너비`만 바꿔 쓴다. 모든 탭·패널이 같이 쓰고 재시작해도 남는다. 파일 행에는 손잡이가 없고 이름 컬럼은 남는 폭을 차지한다. 손잡이는 헤더에 `|` 표시로 보이고(컬럼 세로선을 켜면 그 선이 대신한다), `behavior.table.column_lines`(`none`·`solid`·`dash`)로 컬럼 사이 세로선을 헤더와 모든 행에 그릴 수 있다.

**파일 목록 아이콘**: 각 행 앞의 아이콘은 이 앱의 머티리얼 아이콘이다(파일 이름·확장자·폴더 이름 규칙). 설정 `behavior.table.system_icons`(기본 `false`)를 켜면 운영체제가 그 파일 종류에 쓰는 아이콘(Finder·탐색기와 같은 것)으로 바꿔 보인다. 폴더는 폴더 아이콘이고(macOS의 디스크 위 `.app`은 앱 자기 아이콘), 파일은 확장자로 종류 아이콘을 얻으며 압축 안 항목도 확장자로 얻는다. 응답이 오기 전과 얻지 못했을 때(Linux, 오류)는 머티리얼 아이콘이 그대로 보여 자리가 바뀌지 않는다. 상위 폴더 `..` 행과 심볼릭 링크 표식(`↗`)은 바뀌지 않는다. 아이콘은 `icon_size × 화면 배율`을 16·32·64·128px 중 올림한 크기로 요청하며 같은 종류는 한 번만 묻는다. 끄면 요청 없이 머티리얼 아이콘으로 돌아온다. 아이콘의 실제 모양은 운영체제가 정하고, Windows는 아이콘의 실제 크기(16·32px)로 주므로 요청 크기와 다를 수 있으며 화면이 `icon_size`에 맞춰 그린다. Windows에서 디스크 위 `exe`·`lnk`·`ico` 같은 파일은 자기 아이콘을 쓴다.

### 4.3 커서, 선택, 상호작용

| 규칙 | 내용 |
|---|---|
| 커서 | 한 행만 가진다. 방향키로 이동한다 |
| 선택 | 커서와 별도의 집합. `Shift+이동`은 지나간 범위의 선택을 반전하고(기본), `selection.shift_mode = "extend"`로 일반적인 범위 확장으로 바꿀 수 있다 |
| 마우스 | 클릭으로 커서 이동, `Ctrl/Cmd+클릭`으로 선택 토글, 드래그로 범위 선택, 더블클릭으로 열기 |
| 대상 해석 | 선택이 있으면 선택 항목이, 없으면 커서 항목이 작업 대상이다 `[중간]` |
| 상위 폴더 이동 | 기본은 목록 위에 `..` 줄을 두지 않는다(이슈 #22). 설정 `behavior.table.show_parent_row`(기본 꺼짐, 이슈 #44)를 켜면 목록 맨 위에 `..` 행이 보이고 `Return`·더블클릭으로 올라간다. `..`는 폴더에 들어갈 때 커서가 놓이는 자리가 아니라 `↑`로 가는 자리이고, 전체 선택·선택 토글·복사·이동·삭제·이름 바꾸기·경로 복사의 대상에는 절대 들지 않으며(커서가 `..`이고 선택이 없으면 그 작업은 아무 일도 하지 않는다), 루트와 검색·Disk Usage 같은 가상 탭에는 없다. `Backspace`, `←`(여러 컬럼 보기가 아닐 때), Windows·Linux의 `Alt+↑`, 경로 표시줄의 상위 조각 클릭으로 올라간다 |
| 인라인 이름 변경 | 이름 변경 액션(`F2`, `Shift+F6`)이 별도 창 없이 커서 행의 이름 칸을 입력칸으로 바꾼다(이슈 #65). 처음에 파일은 `.` + 확장자를 뺀 부분이, 폴더는 이름 전체가 선택된다. `Return` 저장, `Esc` 취소, `↑`/`↓`는 저장한 뒤 편집 전 위치 기준 위/아래 항목의 편집으로 넘어간다(맨 위·맨 아래면 저장하고 끝낸다). 중복·쓸 수 없는 문자로 저장에 실패하면 알리고 그 자리에서 편집을 이어 간다. 다른 곳을 누르거나 창이 포커스를 잃으면 저장하고, 이때 실패하면 알리고 편집을 끝낸다 |
| 드래그 앤 드롭 | 행에서 마우스를 누른 채 5px 이상 움직이면 드래그가 시작되고, 앱이 마우스 이벤트로 직접 처리한다(브라우저 드래그는 운영체제가 커서의 +를 정해 Ctrl 상태를 보여 줄 수 없어서 쓰지 않는다). 커서 옆에 복사(+) 또는 Ctrl이 눌려 있는 동안 이동(−) 표시와 항목 이름·수가 따라다닌다. 다른 패널(빈 곳이면 그 패널의 현재 폴더)이나 폴더 행(안으로)에 놓으면 복사하고, 놓을 때 Ctrl이 눌려 있으면 이동한다. 선택된 행을 끌면 선택 전체, 선택에 없는 행을 끌면 그 행만 간다. 같은 패널의 빈 곳이나 가상 탭에는 놓을 수 없다. Esc로 취소한다. 이름이 겹치면 충돌 창을 쓴다. 마우스가 창 밖으로 나가면 운영체제 드래그(`start_native_drag`, `drag` 크레이트)로 넘어가 Finder·탐색기 같은 다른 앱에 놓으면 복사된다(macOS·Windows. 아카이브 안의 항목은 보낼 수 없다) **Finder에서 끌어 온 파일**(다른 앱에서 끌어 온 것 모두, 이슈 #39)도 패널에 놓을 수 있다. 이 경우 OS가 끌기 그림을 그리고 놓기는 Tauri의 드래그 앤 드롭 이벤트로 오며 수정키 정보가 없어 **항상 복사**한다. 놓을 곳은 앱 안 끌기와 같다(폴더 행 위면 그 폴더 안으로, 아니면 그 패널의 현재 폴더, 가상 탭에는 알림만, 패널 밖은 무시). 끄는 동안 대상 패널·폴더 행이 강조되고, 이미 그 폴더 안에 있는 항목은 건너뛰며, 이름이 겹치면 같은 충돌 창을 거친다. |
| 날짜 구간 그룹핑 | 설정 `behavior.table.group_by_modified`(기본 꺼짐, 이슈 #62)를 켜면 단일 컬럼 목록 보기에서 파일을 수정일 구간으로 나눠 구간 제목 행을 항목 사이에 보인다. Finder의 날짜별 그룹과 같은 구간이며 최신 구간이 위다: `오늘` · `어제` · `이전 7일` · `이전 30일` · 이번 해는 월별(`6월`) · 지난 해는 연도별(`2025`) · 수정일이 없으면 맨 아래 `날짜 없음`. 로컬 자정으로 `오늘`·`어제`를 가르고, 구간 안은 현재 정렬(폴더 먼저)을 따른다. 제목 행은 선택·커서 대상이 아니고 항목 수에 들지 않아 `↑`/`↓`가 건너뛴다. 여러 열 보기와 가상 탭(검색 결과·Disk Usage 등)에는 적용하지 않는다 |
| 신선도(수정일) 밝기 | 설정 `behavior.table.freshness`(기본 꺼짐, 이슈 #91)를 켜면 이름 칸의 글자색을 수정일 단계로 나눈다: 3 = 7일 이내(오늘·앞날 포함, 앱 글자색) · 2 = 30일 이내 · 1 = 1년(365일) 이내 · 0 = 그 이상과 날짜 없음(흐린 글자색). 경계는 날짜 구간 그룹핑과 같은 로컬 자정이다. 색이 아니라 밝기만 쓴다(내장 테마 112개 중 80개는 글자색이 무채색이라 채도로는 나눌 수 없다). 가장 흐린 단계는 테마의 `ink-dull`(직접 지정한 글자색이면 배경 30% 섞음)이되 배경과 대비 4.5를 지키고, 사이 단계는 OKLab에서 고르게 섞는다. 이웃 단계의 ΔE가 0.02보다 좁으면(글자색이 이미 대비 4.5 언저리인 Solarized Light·Dark, Tokyo Night Day 등) 적용하지 않고 설정 항목 아래에 이유를 경고 색으로 보인다. 선택한 행·꽉 채운 커서 행·이름 바꾸는 중인 칸은 원래 색이다. 색은 `<html>`의 `--fresh-0`~`--fresh-3`이다 |
| 가상 스크롤 | 화면에 보이는 행만 렌더링한다 |

### 4.4 Quick Select

수정자 없는 문자를 입력하면 입력 상자가 목록 위에 나타나고 일치 항목으로 커서가 이동한다. 기본은 부분 일치이며 `quick_select.match_only_prefix`로 접두 일치로 바꾼다. 정규식 입력은 홈페이지에 "substring or regex"로 언급되나 입력 문법은 확인하지 못했다 `[알 수 없음]`. 입력 중 `↑`/`↓`는 입력과 일치한 행들 사이에서만 커서를 옮기고(일치하지 않는 행은 건너뛰며 끝에서 멈춘다), `Return`은 Quick Select를 끝내고 커서 행을 연다(폴더면 들어가고 파일이면 기본 열기). `Escape`가 선택 해제와 Quick Select 종료를 겸한다. 키 충돌 규칙은 [05](05-actions-keybindings.md#32-단일-문자-키와-quick-select의-충돌).

한글 IME가 `keydown`으로 낱개 자모(`ㅎ`, `ㅏ`, `ㄴ`)를 보내면 버퍼를 `es-hangul`의 `assemble`로 다시 음절로 조립한다(`ㅎㅏㄴㄱㅡㄹ` → `한글`). `Backspace`는 마지막 음절에서 자모 하나만 지운다(`한글` → `한그` → `한ㄱ` → `한`). 한글 초성도 검색한다: `ㅎㄱ`은 `한글 문서.txt`에 일치하고 `한ㄱ`처럼 음절과 초성을 섞어도 된다(`quick_select.match_only_prefix`가 켜져 있으면 이름 앞에서만, 일치한 부분은 하이라이트된다). 입력 도중의 미완성 음절(`하`가 `한`에 일치)은 아직 지원하지 않는다. 한계: 실제 macOS WKWebView에서 IME가 보내는 `keydown`의 `e.key`가 낱개 자모인지는 이 저장소의 테스트가 덮지 못해 사람이 확인해야 하고, Windows에서 한글 상태가 영문으로 바뀌는 문제(이슈 #87)는 아직 고치지 않았다.

## 5. 팝업 메뉴

Volumes, Favorites, Recent Locations, Hierarchy는 모두 같은 형태의 팝업 목록이다. 방향키 또는 숫자키로 항목을 고르고 Return으로 이동한다.

| 메뉴 | 단축키(macOS/Win-Linux) | 내용 |
|---|---|---|
| Volumes | `Alt+1` | 마운트된 볼륨. 항목에서 언마운트/추출 |
| Favorites | `Alt+2` | 즐겨찾기 (숫자키로 상위 항목 선택). 추가/편집 액션 |
| Recent Locations | `Alt+3` | 최근 위치(양쪽 패널 공용) |
| Hierarchy | `Alt+0` | 루트까지의 상위 폴더 목록 (브레드크럼과 같은 정보) |

## 6. 다이얼로그

| 다이얼로그 | 동작 |
|---|---|
| 복사/이동 확인 | 대상 경로(비활성 패널 위치)를 기본값으로 보여 주고 수정 가능. 비활성 패널로 복사/이동 액션은 이 창을 생략 |
| 삭제/휴지통 확인 | `core.confirm.delete`, `core.confirm.trash` 설정에 따라 표시. 기본은 영구 삭제만 확인 |
| 이름 충돌 | 덮어쓰기, 건너뛰기, 이름 바꿔 복사, 모두에 적용. 큐 작업 중이면 큐가 일시 멈추고 이 창을 띄움 |
| 새 폴더/새 파일 | 이름 입력. 폴더는 중첩 경로(`a/b/c`) 허용 (OP-01) |
| Go To Path | 입력 + Tab 완성. 아카이브 안에서는 `/`가 아카이브 루트 (NAV-11) |
| 파일 정보 | 이름, 경로, 종류, 크기, 생성/수정/접근 시간, 권한 |
| Open With | 앱 목록. OS별 ([09](09-platform-support.md)) |

모든 다이얼로그는 키보드만으로 조작 가능해야 하며(Return 확인, Escape 취소, Tab 이동), 포커스는 열릴 때 첫 입력에, 닫힐 때 원래 패널에 돌아간다.

## 7. 작업 큐 UI

```
큐 진행 표시(우상단) 클릭 또는 `=`
        ↓
   ┌ 팝업 ───────────────────────────┐
   │ ▶ 복사 12개 → /Volumes/USB  63% │  ← 방향키/Space로 선택
   │   이동 3개  → ~/archive     대기 │
   └ P 일시정지 · A/D 중단 · Esc 닫기 ┘
```

- 실행 중인 작업은 진행률, 현재 파일, 남은 항목을 표시한다.
- 복사·이동의 진행 창은 현재 파일의 바이트를 알게 되면 막대 2개를 보인다(집계 직후 그 전에는 전체 개수 막대 1개). 위는 지금 처리 중인 파일(`현재 파일`)의 바이트 진행, 아래는 전체 진행(처리한 파일 수/전체 파일 수)이다. 파일이 1개이면 현재 파일 막대만 보인다. 삭제·휴지통·압축·풀기는 막대 1개다.
- 실패한 항목은 작업 종료 후 요약으로 보여 준다.
- 진행 창이 뜨기 전에(삭제·휴지통은 시작 후 300ms 안에) 실패로 끝난 작업은 진행 창이 없으므로 상태 표시줄에 알림(`삭제 실패: <경로>: <사유>`, 항목이 여럿이면 `(외 N건)`)으로 알린다. 진행 창이 그 작업을 보이고 있으면 창의 오류 목록이 대신하고 알림은 띄우지 않는다.
- 큐가 비면 진행 표시는 사라진다.

## 8. 미리보기와 정보

- `Space` 또는 `Mod+Y`로 커서 항목을 미리 본다. 이미지, 텍스트(구문 강조), 오디오/비디오부터 지원하고(Spacedrive의 QuickPreview 포팅) 나머지는 아이콘과 정보만 보인다.
- **미리보기 창 이동·크기 조절** (이슈 #11): 미리보기 창은 제목 줄을 끌어 옮기고, 네 가장자리와 네 모서리를 끌어 크기를 바꾼다. 제목 줄을 더블클릭하면 기본 크기(너비 44rem, 높이 화면의 80%)·가운데로 돌아간다.
  - 이동: 창의 왼쪽·위쪽은 화면 안에 두고, 제목 줄이 최소 64px는 화면에 남는다.
  - 크기: 최소 320×200px(화면이 더 작으면 화면 크기), 최대는 화면 크기다. 왼쪽·위를 끌면 반대편 변이 제자리에 남는다.
  - 기억: 바꾼 위치·크기는 `state.json`의 `previewRect`에 저장돼 닫았다 다시 열거나 다른 파일로 넘겨도, 앱을 다시 켜도 이어진다. 화면보다 커졌거나 밖에 걸린 값은 열 때 화면 안으로 보정한다. 키보드로는 옮기지 않는다.
- **텍스트 복사 버튼** (이슈 #38): 텍스트 계열 미리보기(텍스트·코드·마크다운·JSON)의 제목 줄, ✕ 바로 왼쪽에 복사 **아이콘 버튼**(글자 없음, 접근성 이름 `텍스트 복사`)이 있다. 누르면 파일의 **원문**(마크다운·JSON도 렌더링된 글자가 아니라 원문)을 클립보드에 넣고 아이콘이 잠깐(약 1.5초) 체크 표시로 바뀐다. 파일이 64KB를 넘어 앞부분만 보이면 보이는 앞부분만 복사되고 버튼의 `title`이 이를 알린다. 이미지·PDF·오디오·비디오·폴더·기타·3D·Office 미리보기에는 버튼이 없다. 본문은 드래그로 선택할 수 있고(`select-text`) 선택 뒤 `Cmd/Ctrl+C`는 미리보기 키 범위(`preview`)에서 파일 복사에 묶여 있지 않아 브라우저 기본 복사가 동작한다.
- **이미지 복사 버튼** (이슈 #88): 이미지 미리보기(그림이 실제로 보일 때)의 제목 줄, ✕ 바로 왼쪽에 복사 **아이콘 버튼**(접근성 이름 `이미지 복사`)이 있다. 누르면 그 이미지를 운영체제 클립보드에 **이미지로** 넣고(다른 앱에 붙여 넣을 수 있다) 아이콘이 잠깐 체크로 바뀐다. 복사하지 못하면 아이콘은 바뀌지 않고 오류 알림이 뜬다. `Mod+C`(`core.preview.copy`)도 같은 동작이며, 이미지가 아닌 미리보기에서는 선택한 글자를 복사한다(선택이 없으면 아무것도 하지 않는다). 압축 파일 안 이미지도 복사된다. SVG와 너무 커서 표시하지 못한 이미지는 복사하지 않는다. 한계: 실제 운영체제 클립보드에 이미지가 들어가는지와 다른 앱에서 붙여 넣은 모습은 자동 시험이 덮지 못해 사람이 확인해야 한다.
- **더블클릭으로 편집하고 `Mod+S`로 저장** (이슈 #38): 텍스트 계열 미리보기의 본문을 더블클릭하면 원문 편집 상자로 바뀐다(마크다운·JSON·코드도 원문). 제목 줄에 `편집 중`(변경이 있으면 `●`)이 보이고 `Mod+S`로 저장하면 저장 뒤에도 편집이 유지되며 잠깐 `저장됨`이 보인다. 편집은 **디스크 위의 일반 파일이고 전체가 읽혔고(64KB 이하) UTF-8 텍스트이며 줄바꿈이 LF만이거나 CRLF만일 때만** 시작하고, 아니면 이유를 알리고 시작하지 않는다(압축 안 파일, 일부만 보이는 파일, 섞인 줄바꿈 등 — 저장하면 파일이 망가질 수 있는 경우). 저장은 같은 폴더의 임시 파일에 쓴 뒤 이름을 바꾸는 원자적 쓰기이고 권한을 유지하며, 파일이 CRLF였으면 CRLF로 되돌려 쓴다. 편집을 시작한 뒤 파일이 밖에서 바뀌었으면(크기·수정 시각 비교) 쓰지 않고 `덮어쓰기 / 취소`를 묻는다. 편집 상자가 있는 동안 글자·방향키·`Space`·`Enter`·`Delete`는 상자가 받고 `Esc`는 미리보기 닫기가 아니라 편집 종료다. 저장하지 않은 변경이 있을 때 편집이 끝나는 동작(`Esc`, ✕, 바깥 클릭, 이웃 파일 이동, 삭제, `Return`)은 `저장 / 버리기 / 취소`를 먼저 묻는다. 한계: macOS의 NFD 이름 파일(SMB 공유)처럼 이름 정규화가 다른 경로는 저장이 오류로 끝난다(쓰지 않으므로 파일은 안전하다).
- **Markdown 링크** (이슈 #89): 링크는 눌리는 요소(`role=link`, 포커스 후 `Enter`)이고 웹뷰가 앱 화면을 링크 주소로 바꾸지 않는다. `http(s)://`·`mailto:`는 OS 기본 열기 명령으로 기본 브라우저·메일 앱에서 연다(스킴을 `http`·`https`·`mailto`로 한정하고 공백·제어 문자가 든 주소는 거부한다). `#제목`은 같은 문서의 그 제목으로 스크롤한다(제목에는 GitHub 방식 id: 소문자, 글자·숫자·`_`·`-`만 남기고 공백은 `-`, 같은 제목이 둘이면 첫 번째로 간다). 상대 경로(`./a.md`, `docs/b.md`, `../c.md`, `%20`)는 마크다운 파일이 있는 폴더 기준으로 풀어 파일이면 그 폴더로 패널을 옮겨 미리보기로 열고, 폴더면 미리보기를 닫고 그 폴더로 이동하며, 없는 항목은 "링크한 항목을 찾을 수 없습니다"를 알린다. 그 밖의 스킴(`javascript:`·`file:`·`data:`)과 `/`로 시작하는 경로는 눌러도 아무 일도 하지 않는다. `파일.md#제목`은 파일만 연다. Office 문서의 Markdown 본문은 외부 링크만 열린다.
- **마크다운의 상대경로 이미지** (이슈 #42): 디스크 위 `.md` 미리보기에서 `![](img/a.png)`·`./a.png`·`../pics/b.png`·`%20`(공백)로 쓴 이미지를 마크다운 파일이 있는 폴더 기준의 파일 주소(asset 프로토콜)로 보여 준다. 바깥 주소(`https:` 등)·`data:`·`javascript:`·절대경로 이미지는 불러오지 않고 대체 텍스트만 보이며, 압축 안 마크다운과 폴더 루트를 벗어나는 경로도 같다. 원시 HTML과 링크 이동은 이전처럼 막혀 있다.
- **원격 파일 미리보기**: 원격(`sftp://`·`ftp://`) 패널에서 `Space`/`→`로 파일을 열면 텍스트·코드·Markdown·JSON(앞 64KB)과 이미지(`preview.image_max_mb` 안, 넘으면 "너무 커서 미리 볼 수 없습니다")만 보인다. 서버에서 앞부분만 읽고 이미지는 한도 안에서만 내려받는다. 보기 전용이라 본문 더블클릭 편집은 "원격 파일은 미리보기에서 편집할 수 없습니다"로 막히고, 복사 버튼·`Mod+C`·이미지 복사는 그대로 된다. PDF·동영상·오디오·Office·epub·HWP·3D는 앱이 로컬 파일 주소로 읽는 뷰어라 쓰지 않고 `미리 볼 수 없는 형식입니다`로 보인다(압축 파일 안과 같다). 로컬 패널로 복사(`F5`)하면 모든 형식으로 볼 수 있다.
- **epub 미리보기**: 디스크 위 `.epub`을 열면 본문 맨 위에 머리말(표지 이미지·제목·저자)과 목차 선택 상자(접근성 이름 `목차`)가 있고 그 아래에 현재 챕터가 나온다. 챕터는 스크립트 없는 격리 iframe(`sandbox="allow-same-origin"`)에 그려지며 챕터 안 이미지·스타일은 포함되고 스크립트는 빠진다. 챕터 이동은 시트 전환과 같은 `Ctrl+Tab`/`Ctrl+Shift+Tab`(끝에서 처음으로 돌아감)과 목차 상자이고, 바꾸면 본문이 맨 위로 돌아간다. `↑`/`↓`(이웃 파일)와 PageUp/PageDown(스크롤)은 그대로다. DRM이 걸렸거나 깨졌거나 파일이 100MB·챕터가 2MB를 넘으면 `미리 볼 수 없는 형식입니다 (이유)`로 보이고, 압축 파일 안의 epub은 읽지 않는다. 챕터 안 이미지는 `preview.image_max_mb`를 따른다. 보기 전용이라 복사 버튼과 편집은 없다.
- **Office 문서 미리보기**: 디스크 위 docx·xlsx·pptx·doc·xls·ppt·docm·xlsm·pptm을 열면 본문 맨 위에 "데이터 미리보기이며 실제 문서 화면과 다릅니다"가 고정돼 있고(스크롤해도 따라온다) 그 아래에 office_oxide가 읽은 글자와 표(Markdown, 접근성 이름 `Office 문서 미리보기`)가 나온다. 20MB를 넘거나 깨진 파일은 안내 문구(`role=alert`)로, 압축 파일 안의 문서는 `미리 볼 수 없는 형식입니다`로 보이고, 결과가 길면 `첫 부분만 표시합니다`가 붙는다. 설정 스위치는 없다. 보기 전용이라 복사 버튼과 편집은 없다.
- **HWP 미리보기**: 디스크 위 `.hwp`·`.hwpx`를 열면 본문 맨 위에 `1 / N쪽` 표시가 있고 그 아래에 현재 쪽이 실제 조판대로 나온다. 쪽은 SVG를 Blob URL로 `<img>`에 넣어 그리므로 문서 안 스크립트는 실행되지 않는다. 쪽 이동은 시트 전환과 같은 `Ctrl+Tab`/`Ctrl+Shift+Tab`(끝에서 처음으로 돌아감)이다. 파일이 20MB를 넘으면 `한글 문서가 너무 커서 미리 볼 수 없습니다`, 암호가 걸렸거나 깨졌으면 `한글 문서를 읽을 수 없습니다: 이유`로 보이고, 압축 파일 안의 HWP는 읽지 않는다. 한컴 전용 글꼴은 번들하지 않아 시스템 글꼴로 대체되므로 줄바꿈이 원본과 다를 수 있다. 보기 전용이라 복사 버튼과 편집은 없다.
- Marta가 macOS Quick Look을 쓰는지는 확인하지 못했다 `[알 수 없음]`. twin-deck은 3개 OS 일관성을 위해 앱 내 미리보기로 구현하고, macOS Quick Look 연동은 선택 사항으로 남긴다. (Office 문서는 OS와 관계없이 office_oxide로 읽은 글자·표 미리보기를 쓴다: ADR-0020. 한때 쓴 macOS Quick Look·Windows 미리보기 처리기는 ADR-0020으로 대체되어 지웠다.)

## 9. 가상 탭

Disk Usage, Look Up, Flatten의 결과는 위치가 없는 탭에 표시한다(PANE-06).

| 가상 탭 | 내용 | 열기 액션 |
|---|---|---|
| Disk Usage | 하위 폴더별 크기, 크기 내림차순 | `core.disk_usage` |
| Look Up | 검색 결과 목록 | `core.lookup.*` |
| Flatten | 현재 폴더 하위의 모든 파일을 평면 목록으로 | `core.flatten` |

가상 탭의 항목도 일반 항목처럼 선택하고 복사/이동/삭제할 수 있고, 항목에서 "해당 폴더로 이동"이 가능해야 한다. 종료(탭 닫기)하면 결과는 버린다.

## 10. 빈 상태와 오류 상태

| 상황 | 표시 |
|---|---|
| 빈 폴더 | "항목 없음" 문구만 |
| 권한 거부 | 목록 영역에 오류 배너와 상위로 이동/재시도. macOS에서는 전체 디스크 접근 권한 안내 ([09](09-platform-support.md)) |
| 폴더가 사라짐(감시 이벤트) | 가장 가까운 존재하는 상위 폴더로 자동 이동하고 알림 |
| 볼륨 분리 | 해당 볼륨을 보던 탭은 홈으로 이동하고 알림 |
| 큐 작업 실패 | 항목별 오류 요약 |
| 설정 오류 | 상태 표시줄에 경고 아이콘, 클릭하면 목록 |

## 11. 접근성

- 모든 기능이 키보드로 가능하다(성공 기준, [00](00-overview.md)).
- 목록은 `role="grid"` 또는 `listbox` 시맨틱을 갖고 커서 행을 `aria-activedescendant`로 노출한다. 가상 스크롤에서도 보이지 않는 행에 대한 총 개수/위치 정보(`aria-rowcount`, `aria-rowindex`)를 제공한다.
- 색만으로 상태를 구분하지 않는다(활성 패널, 선택, 커서는 테두리/아이콘/굵기를 함께 쓴다).
- 색 대비는 WCAG AA를 목표로 한다. 검증은 M2 테마 확정 때 한다.

## 11.1 설정 화면

`Mod+,`(`core.settings.open`)로 설정 화면을 연다. 설정은 메인 창 전체를 덮지 않고 **활성 패널 자리**(지금 활성인 패널)에 뜬다. 반대쪽 패널은 그대로 보여서, 값을 바꾸면 그 결과가 바로 확인된다. Esc로 닫으면 그 패널의 원래 탭과 목록이 돌아온다. 구현됨(2026-10-01), 패널 안으로 옮김(2026-10-08, 이슈 #31).

- 배치: 활성 패널 전체(드라이브·탭·경로·목록)를 설정 화면이 대신한다. 위쪽 제목 줄(업데이트 확인, 설정 폴더 열기, 닫기), 그 아래 왼쪽에 세로 섹션 탭 줄(폭 11rem, 넘치면 세로 스크롤), 오른쪽에 한 섹션. 섹션은 그룹 제목 아래에 묶는다: 화면(모양(언어 선택 포함, 이슈 #32), 목록과 선택, 표시 형식, 미리보기), 동작(확인, 폴더 단축키, F키), 시스템(환경), 연결(SMB 서버, SFTP·FTP 서버). 섹션이 늘어 위쪽 가로 탭 줄이 불편해져 세로로 바꿨다. 대신 탭 줄이 패널 폭을 11rem 가져가므로 패널을 아주 좁히면 항목 폭이 줄어든다. 그룹은 `SECTION_GROUPS`로 정하고 탭 번호(`settingsSection`)는 섹션 순서 그대로다.
- 항목은 값 하나짜리 14개다. 스위치(`@spacedrive/primitives` Switch), 선택(Select), 숫자·문자 입력(Input)을 쓴다. 배열 설정(컬럼, Action Bar 목록, 즐겨찾기, zip 확장자)과 키바인딩, `shift_mode`, `terminal`은 넣지 않았다. 그런 것은 설정 폴더 열기로 파일을 고친다.
- 바꾸는 즉시 사용자 `config.toml`의 그 키만 쓴다(`toml_edit`로 주석, 다른 키, 순서를 보존한다). 스위치와 선택은 바꾸는 순간, 입력창은 Enter나 포커스를 벗어날 때 저장한다.
- 값이 기본값과 다르면 항목 옆에 되돌리기(반시계 화살표) 아이콘 버튼(접근성 이름 "기본값으로")이 나오고, 마우스를 올리거나 포커스하면 "기본값으로" 말풍선이 뜬다. 누르면 그 키를 사용자 설정에서 지운다. 버튼 자리(24px)는 기본값일 때도 비워 두어 값을 바꿔도 줄의 배치가 움직이지 않는다. F키 조합 줄의 "삭제"는 글자 버튼 그대로다.
- 쓴 직후의 설정은 Tauri 명령의 응답으로 받아 바로 적용한다. 파일 변경 이벤트를 기다리지 않는다.
- `config.toml`에 문법 오류가 있으면 파일을 건드리지 않고, 화면 위에 알리고 컨트롤을 비활성화한다.
- 키 스코프는 `settings`다. 열려 있는 동안 패널 키는 무시된다. 설정이 열려 있는 동안 반대쪽 패널은 눌러도(클릭·더블클릭·우클릭·끌기) 설정이 유지되고 활성 패널도 바뀌지 않는다(결과를 보는 용도, 휠 스크롤만 된다).

### SFTP 서버 신원 확인

처음 보는 host/port에 연결하면 비밀번호 인증 전에 접속 대상, 키 알고리즘, SHA256 지문을 표시한다. 사용자는 서버 관리자 등 신뢰할 경로의 지문과 대조한 뒤 지문 일치 확인란을 선택하고 ‘승인하고 연결’을 눌러야 공개 키 저장을 승인할 수 있다. 확인 전에는 승인 버튼이 비활성이다. 기본 포커스는 취소이며, 미확인 상태·취소는 키 저장과 인증을 하지 않는다. 저장된 자격증명도 이 검증을 우회하지 않는다. 재접속은 저장 키와 비교하며, 변경되면 기존/새 지문과 서버 사칭 위험을 표시하고 차단한다. 키 교체 UI는 제공하지 않는다. 저장 실패도 연결을 차단한다. 신뢰 키는 이 기기의 기본 앱 설정 폴더 `sftp-host-keys/`에만 저장하고 범용 설정 동기화·내보내기와 분리한다.


### 끊긴 원격 연결 다시 연결 (이슈 #98)

원격(SFTP·FTP) 연결이 끊기면 그 탭을 읽을 수 없다. 목록을 읽다가 "원격 연결이 끊어졌습니다"(끊긴 세션)·"원격 연결이 열려 있지 않습니다"(세션 없음)·"서버에 연결할 수 없습니다"(서버에 닿지 않음) 오류가 나면 그 패널의 목록 영역을 흐리게 하고 가운데에 연결이 끊어졌다는 안내, 연결 id, 서버가 준 오류 문구와 **다시 연결** 버튼을 보인다(권한 없음 같은 다른 오류는 이 오버레이 없이 기존 오류 줄만 보인다). 누르면 설정의 서버 항목으로 "연결"과 같은 흐름(저장된 비밀번호, 없거나 틀리면 비밀번호 창, 처음 보는 호스트 키 확인)으로 다시 접속하고, 성공하면 그 연결을 보는 모든 탭(양쪽 패널·배경 탭)을 다시 읽어 복구한다. 연결하는 동안 버튼은 꺼지고 "연결하는 중…"으로 바뀌며, 취소·실패하면 오버레이가 남는다. 액션 패널의 `core.remote.reconnect`("원격 다시 연결", 기본 단축키 없음)가 같은 일을 한다. 설정에서 지워진 서버의 탭은 다시 연결하지 않고 알림만 보인다. Rust는 같은 서버에 다시 연결할 때 끊긴 세션을 레지스트리에서 버리고 새로 접속한다(전에는 죽은 세션이 남아 앱을 다시 시작할 때까지 계속 실패했다). 끊김은 그 탭을 다시 읽을 때(폴더 이동·파일 작업) 알게 되고 자동 재연결은 없다. 원격 터미널 탭은 이 오버레이 대상이 아니다.

### 연결 메뉴의 종류 배지와 Shift+숫자 (이슈 #95)

드라이브 바의 "서버에 연결" 메뉴(`Alt+4`, `core.menu.connect`)는 항목 이름 **앞에 연결 종류 배지**를 붙여 SMB·SFTP·FTP·Twin Deck을 구분한다. 배지는 shadcn badge 같은 작은 알약 모양이고(`ui/ProtocolBadge.tsx`) 종류마다 색이 다르다: SMB 파랑(`status-info`), SFTP 초록(`status-success`), FTP 경고색(`status-warning`, 암호화되지 않음), Twin Deck 강조색(`accent`). 색에만 기대지 않도록 글자를 늘 함께 보이고 화면 읽기 프로그램도 읽는다("SFTP 회사"). 항목 이름에는 예전의 `SFTP · ` 접두사를 더 붙이지 않고, 순서는 `[배지] [아이콘] 이름`이다. 연결 중이라 비활성인 항목에도, 서버 관리(…관리) 항목에는 없다. 이 메뉴에서 SFTP 항목의 `Shift+숫자`(n번째 항목, 키 위치 `Digit1`~`Digit0`로 번호를 읽음)는 숫자만 누를 때의 연결 대신 연결한 뒤 SSH(원격 셸) 터미널 탭을 연다. SFTP가 아닌 항목이나 범위 밖 번호는 아무 일도 하지 않고, 숫자를 Shift로 치는 배열(AZERTY 등)처럼 `e.key`가 숫자 자체로 오면 일반 숫자 선택으로 둔다. 메뉴 아래 도움말이 이를 알려 준다.

### SFTP 터미널 연결 (이슈 #94)

연결 메뉴·설정의 "연결"은 현재 탭을 서버로 옮기지 않고 그 패널에 서버 루트를 보는 새 탭을 연다(그 패널에 서버 루트를 이미 보는 탭이 있으면 그 탭으로 간다).

설정의 SFTP·FTP 서버 탭에서 SFTP 서버를 고르면 "연결" 옆의 "터미널 연결" 버튼이 켜진다(FTP·항목 없음은 꺼짐). 누르면 "연결"과 같은 순서(변경분 저장 → 설정 닫기 → 비밀번호·호스트 키 확인)로 서버에 연결해 그 서버의 원격 셸 터미널 탭만 설정이 덮고 있던 현재 패널의 탭 줄에 연다(패널은 서버 폴더로 옮기지 않는다). 연결이 실패하거나 취소되면 터미널은 열지 않는다.

SFTP 승인 통합 회귀 시험은 `cargo test -p twin-deck-desktop --no-run`으로 테스트 실행 파일을 만든 뒤, `apps/desktop`에서 `TWIN_DECK_SFTP_TEST_BINARY=<출력된 테스트 실행 파일의 절대 경로> bunx vitest run src/__tests__/sftp-connection.integration.test.tsx`로 실행한다. UI와 생성된 Tauri 호출·DTO 직렬화, Rust의 실제 연결 경로를 임시 로컬 SFTP 서버에 연결한다(시험 전송은 stdin/stdout이며 네이티브 WebView IPC 자체는 제외). 임시 신뢰 저장소와 가짜 비밀번호만 사용하며 첫 취소 시 인증·저장 0회, 승인 후 성공, 연결 해제 후 팝업 없는 재접속을 검증한다. 일반 Vitest 실행에서는 Rust 테스트 실행 파일을 지정하지 않으면 이 시험을 건너뛴다.
